## 1. Inspora：3D 渐变卡片

来源：https://x.com/insporadesign/status/2100559994705915917

原帖署名作品来自 @basit_designs。实际画面以白底承托蓝、紫、暖色卡片；主卡片的透视、光色与外围卡片的相对位置制造焦点。局部信息和大数字留在卡片上，卡片本身成为可记住的视觉对象。

**借鉴：** 官网需要一件主视觉作品，展示「课程 → 出行 → 一起」三种校园时刻；主卡明确、配角退后，颜色有时间/场景含义。用场景卡片和细节放大表达产品价值。

**不照搬：** 不把 3D、变形和高饱和渐变放进课表正文与 ETA 列表；不复制视频素材或把演示中的数字当我们的数据。手机用点击/滑动表达选择，不能依赖鼠标悬停。

**落点：** 官网首屏主视觉、活动专题封面。页面信息/交互完整时才加场景运动；静止时也应独立成立。

## 2. Su：将设计分析变成可复用判断规则

来源：https://x.com/Sukiea1008/status/2099911306338091289

这条是对第三条文章的推荐，并展示保存图文的工作截图。它不是另一套 UI，也没有证明「把文章放进 Skill 就会得到优秀设计」。

**借鉴：** 将原则变成检查项：同组间距是否小于组间距，图标是否视觉居中，主按钮是否突出，360px 字号能否读清。每项都对应需要修改的对象。

**落点：** 项目设计验收表与 Pencil 组件检查；不因为帖子提及 Skill 就安装一堆重复插件。

## 3. Sisymithus：苹果 UI 的几何、负空间与视觉校正分析

来源：https://x.com/Sisymithus/status/2099827668686659989

文章通过一个组合状态图标讨论黑白面积、下方圆点、数字加入后的拥挤程度、邻近关系、比例与视觉校正。

**值得采用的工作方法：**

- 图标不能仅因 bounding box 一样大就认为重量一致；在实际 20–24pt 看可辨认度与视觉中心。
- 同一对象的标题、时间、地点要紧密成组；不同活动之间应有更明显的距离。
- 圆角、描边、阴影和文字层级先形成约束，再对局部视觉偏差做校正。
- 默认状态需要有清晰主次，同时覆盖长标题、放大文字、深色和错误状态。

**证据边界：** 这是第三方分析，不是 Apple 官方设计文件。作者自己说明部分黄金比例构造带有拟合；文中的设备叙述和生理学简化不作为产品事实或严格科学依据。不设置「所有尺寸必须 1.618」之类规则，也不为了默认状态好看牺牲无障碍。

**落点：** 五个 Tab 图标、卡片标题/时间组、按钮文字与图标对齐、空白和满内容状态。

## 4. Jakub Antalik：Transitions.dev 产品动效

来源：https://x.com/Jakubantalik/status/2099162438016901449

视频将两侧菜单、Toast 和输入控件并列展示，强调静态 UI 到状态变化的完成度。作者回复指向官方工具。

核对：https://transitions.dev/ 与 https://transitions.dev/skill.html

官方页面提供菜单原点展开、弹窗开关、Tab 指示器、卡片尺寸变化、Toast、骨架到内容、图标状态变化等模式；Skill 支持审查与应用规则。站点当前主要给出 CSS / React / TypeScript 实例。它们不能未经适配直接当成 React Native 动画组件。

**优先落点：**

1. 日/周切换：选中背景移动，正文保持空间关系。
2. 活动卡 → 详情：保留标题和封面对应关系，退出回到原卡与滚动位置。
3. 报名：空闲 → 提交中 → 已确认 / 候补 / 失败；成功只在接口回执后出现。
4. 菜单/筛选：从触发控件附近出现；收起不突然跳走，不丢失焦点。
5. 校巴刷新：时刻/来源位置固定，局部状态变化；失败不能留着旧预测假装成功。
6. Toast：短提示、可撤销行为对应真实逻辑；不遮挡主操作。

## 对当前产品的判断

当前官网新增完整功能目录与下午互动示例，但依然以段落、卡片和手机框为主；这只是内容与交互底稿，不能据此宣布符合用户审美。App 已改共享样式，不代表全部画面已设计和验收。Pencil 仅建立了基础组件。先停止批量同质卡片扩展，完成一个代表性完整流程，再将同一规则应用到全部页面。

核心用户收益要在首屏和交互里可见：

- 信息难找 → 下一节课、上客点、活动安排能直接找到。
- 想认识人但怕尴尬 → 先看到具体活动、人数、语言和互动氛围，再决定加入。
- 不想被打扰 → 课表默认私密、参与主动选择、退出与屏蔽清楚。

## 下一轮设计与实现顺序

1. Pencil 重做官网首屏主视觉 + App「今天 → 发现小组 → 详情 → 报名结果」连续画面，含正常、候补、失败和减少动态效果状态。
2. 官网主视觉使用一组有空间关系的场景画面；全部功能保留在可搜索目录，避免首屏变功能清单。
3. App 统一信息层级和控件，再实现有原因的状态过渡；Web 与 Native 分别实现，不把浏览器动画当真机验收。
4. 每个设计点绑定截图/录屏与可操作验收。CSS build 成功只能说明编译成功。

## 建议的动效起点（本项目提案，不是参考视频测量值）

| 场景 | 起点 | 验收 |
| --- | --- | --- |
| 按下反馈 | 100–140ms，约 0.98 缩放或明度反馈 | 点下即响应，不影响触发区域；减少动态效果改用静态色反馈 |
| 菜单 / 轻弹层 | 180–240ms，从触发点缩放/淡入 | 开关都连续，Esc/返回关闭，焦点回到触发点 |
| 卡片到详情 | 280–360ms，连贯位置与尺寸 | 快速返回不闪白、不重置列表位置；低性能设备平滑降级 |
| 确认结果 | 160–220ms，状态文字/图标变化 | 与 API 回执一致，候补/失败不显示成功勾 |
| 官网展示 | 用户触发的一次性场景过渡 | 不劫持滚动；无鼠标、键盘和 reduced motion 均可操作 |

这些范围需要实际设备观察后调整；没有精确帧率实测前不承诺 60/120fps。
