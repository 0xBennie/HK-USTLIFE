# Campus 最新执行 Goal

```text
目标：基于现有 Campus 项目，完成 PRD 的 R1＋R1.1 开发与真实 iOS 验收，形成可供受控学生试用的学习、校园生活与自愿社交 App。持续推进已授权工作，直到验收完成或确实需要外部输入。不能以静态页面、mock、接口测试或编译成功代替产品完成。

一、先核对已有成果
原始项目：/Users/bennie/HKUST/All in one HKUST。
优先检查本任务已有 worktree：/Users/bennie/.codex/worktrees/campus-school-sync/All in one HKUST，分支 codex/campus-school-sync。使用前核实归属、Git 状态及最新交接，不覆盖未提交工作，不在多人共享主目录开发。
阅读 AGENTS.md、docs/PRD.md、docs/product/feature-register.csv、最新 docs/progress 交接，以及对应 API、学校同步规格、design/presentation 和 Pen 文档。用户最新要求优先；逐项核实“已有实现、仅设计、待验证、外部依赖”，不要重做已通过且未变化的工作。既有 Goal 的进度不因重新粘贴提示词而清零。

二、产品体验
以 HKUST 为首个校园，iPhone 优先，采用 Apple 风格，固定“今天、校园、发现、消息、我的”五入口。学习和校园工具独立有用，社交自愿；不默认公开课表、位置或单向联系意愿。
UI 工作前应用项目指定 PUA skill 的原型与证据验证方法。设计要有清楚的信息层级、原生导航、完整反馈和克制动效。先在 Pen 补齐本轮页面、组件及状态，再落实原生交互；Pen、浏览器 mock 和实际 iOS 证据分别记录。

三、完成 R1 基础闭环
1. 学校连接：通过获准的官方认证登录，分别处理 SIS 和 Canvas 数据授权。自动同步正式课表、课程、作业和事件，支持更新、取消、分页、部分失败、重新授权、撤销和去重。私人任务、完成状态和笔记不被覆盖。学校密码只在官方认证界面输入；平台不得收取。Canvas 不等同 SIS 正式课表，ICS 和手动录入仅作备用。
2. 学习：今天、周课表、课程详情、任务和截止日期、私人笔记、提醒相互连接，编辑、完成、返回和重启后状态一致。
3. 校园：校巴路线、方向、运行日、假期、时刻与末班；公共交通；地点、餐饮、设施、学校服务、院系与公开联系人目录。支持搜索、详情、来源、更新时间、收藏、纠错和官方入口。明确区分时刻表、实时预测、过期和未知数据。
4. 社交：校园墙、求助、学习招募、活动的发布、编辑、回复、报名、申请、候补、退出、改期和取消；有真实鉴权、持久化、并发名额控制、举报与屏蔽。活动变化同步到消息及用户自选日程、提醒。
5. 账户与配套：资格状态、个人参与记录、隐私设置、导出、退出与删除；站内消息与 iOS 通知；受限管理后台；完整官网、公开活动分享、支持和反馈。官网清楚标明真实可用、内测与规划能力。

四、完成 R1.1 价值机制
X01 合作组队：角色、语言、投入、节奏、自选时段、共享预览、可选试沟通、双方确认及首次分工；沟通不自动等于入队。
X02 共同专注：从私人任务进入有限时段，说明安静或交流方式，支持开始、结束、退出及自愿回顾，不公开效率排名。
X03 固定小组：可以先参加一次，每场独立确认，区分单次与系列修改、取消和下一场，不自动加入永久群。
X04 再次同行：单方意愿私密，双方同意后才建立联系，可撤回、拒绝与屏蔽。
X05 重要事务：有限可维护场景的条件、材料、步骤、期限、官方来源和私人进度；本人勾选、本人报告提交与官方确认分别记录。来源版本变化需核对，私人日期、日程、提醒及历史保持一致。
同时完成条件筛选、可撤回意向、私密邀请及必要组织者工具。人工协调只能在真实可运营范围内开放，不生成假供给或假参与者。

五、完整规划与本轮边界
保留 PRD 全部需求和 BNBU 对照项。邮件、课程资料深化与获准作业提交、课程组合评估、住房室友、借用与毕业交接、同伴帮助、职业机会、深度地图、Widget/Live Activities、多校、苹果其他设备、AI、Wallet 和支付等，按 PRD 的 R2–R4 登记。未经范围调整，不默认塞入本轮，也不删除或伪装上线。Android 暂缓。

六、执行顺序与交付追踪
先建立需求—Pen—原生页面—API—数据来源—验收证据对照表，以实际缺口排序。
优先收尾在做的完整流程，再完成 R1 基础闭环、R1.1 机制、官网后台一致性和整体 iOS 验收；学校授权准备并行推进。
沿用现有 React Native、Expo、TypeScript 和后端。每个新增接口写清权限、字段、分页、幂等、版本冲突、失败恢复、来源及删除规则。不要把拟议接口合同当成已实现能力。
每个可验收单元保存简短交接：目标、确认决定、worktree、文件、完成状态、实际验证、限制和下一步。不因文档旧状态而忽略更新的代码和验收证据。

七、真实验收
对照 PRD 中 R1/R1.1 适用验收项，使用持久化后端与实际 iOS 模拟器或获准设备，验证两个普通账户及受限管理员。
覆盖重登与重启、返回和草稿、跨页一致性、弱网、未知写入、幂等重试、版本冲突、权限隔离、撤销授权、候补晋级、改期取消、系统提醒、删除和导出。
检查中英文、浅深色、窄屏、字体放大、键盘、安全区、VoiceOver、减少动态和原生动效。通知调度日志不等于通知可见与点击跳转通过；截图和构建成功不等于交互验收。
输出可运行项目、启动说明、更新后的 Pen、功能与 API 覆盖表、真实 iOS 操作证据、测试报告、已知限制及学生试用脚本。试用指标需有分母和观察期，不能用工程测试宣称留存或需求已验证。

八、外部依赖与完成条件
学校应用注册、SIS 批准、Canvas 授权、签名与分发分别核实。缺少外部输入时，先完成申请材料、适配器、错误状态和其他独立开发，再报告具体需要什么；不假连接、不绕过权限、不反复等待同一依赖。
未经适用授权，不部署、上架、购买、创建外部账号、发送真实消息、招募学生或提交学校作业；不启用子代理、不创建新聊天、不改变全局工具。
仅当本轮必要实现、正式学校同步与真实 iOS 开发验收全部通过，才将开发目标标记完成。学校接入未获批时，必须明确报告“可独立开发部分已完成，整体仍未完成”，按 Goal 规则处理真实阻塞。公开发布和学生使用效果另行验收。
```
