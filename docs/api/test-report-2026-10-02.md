## 3. 登录与校巴规则的验证范围

合同检查包含：所有本地引用可解析、操作标识唯一、路径参数匹配、私有操作声明认证、写入声明 CSRF、适用操作声明幂等键，以及 JSON Schema 的示例/负例。负例包括额外学校密码字段、站外跳转、把邮箱控制权当有效学生资格、截止时间冲突、计划班次伪装预测、过期来源伪装新鲜、外部报名链接伪装确认等。

这些检查只验证声明和数据形状，**没有执行服务端权限判断**。例如文档要求 state/nonce/PKCE，不等于已通过重放攻击测试。

校巴独立参考模型覆盖正常工作日、两班之间、恰好发车时刻、末班后、周末、公众假期、服务开始前/结束后/最后一天、UTC 转香港时间、缺少时区、未知假期年份、过期来源、模拟停运/冲突、晚班和学生免费线路。参考夹具只有三条选定方向；人工核对和自动来源比对的范围在上一节分别记录。

没有验证全部校巴数据入库、多站同一车次、临时替代班次发布、公告抓取、实际页面倒计时、原生手机登录和完整 ICS 重复/例外解析。校巴参考函数位于验证脚本中，与产品源代码分离。

详见 [38 项检查记录](test-results/contract-and-rules.txt)、[结构化结果](test-results/contract-and-rules.json)、[官方 Schema 结构验证](test-results/openapi-structure.json)及[既有回归日志](test-results/existing-core-tests.txt)。
