# E5 local website and restricted moderation implementation plan

> Execute inline in this session with superpowers:executing-plans. User explicitly forbids subagents/new chats and authorizes implementation without another plan approval. Keep the current feature branch and staged unit handoff.

**Goal:** Deliver a real local website, public-only activity share pages and admin review interface backed by the existing persisted product API.

**Architecture:** Reuse Next.js `apps/hub`, preserving earlier useful guide routes. Web route handlers implement a narrow same-origin BFF using HttpOnly cookies and explicit CSRF protection; the Fastify API remains the sole identity/role/data authority. Public server-rendered activity pages fetch without cookies/bearer and never preview member/private content.

**Tech stack:** Existing React/Next/TypeScript/CSS; patch Next 16.3.3 to 16.3.8 and compatible vulnerable transitive packages, no extra UI system. Native Expo/HeroUI remains independent.

**Spec:** `docs/superpowers/specs/2026-10-02-ios-mvp-v1-product.md`, V10/MV02/MV07/MV09/MV10/MV11/MV12; this unit does not finish source maintenance, native reminders or iOS acceptance.

## Global constraints

Local-development demo content stays loopback-only; no deploy, real email, external accounts, purchases, school password/API or private data integration. No public-download/availability claims. Both language paths, narrow viewports, keyboard focus and reduced motion. Server role enforcement applies to every admin request. Preserve private calendar isolation. No new chats/subagents or model changes.

## Review focus

- A signed-in administrator opens a member activity share URL: guest fetch and generic metadata/404 prevent private titles from escaping.
- Cross-origin/no-Origin or mismatched CSRF browser writes fail before upstream mutation; preauthentication actions need the same protection.
- Browser reload/restart/expired/revoked/nonadmin session: no bearer in JS/storage, admin roles checked against backend each time, unavailable API fails closed.
- Deleted/reviewed reports and response loss: version conflicts refresh actual server state; no invented success and no duplicate destructive retry.
- API absent, 360px/large text, EN/ZH length and keyboard navigation: honest unavailable/empty states and wrap-safe actions; no fabricated activity supply.
