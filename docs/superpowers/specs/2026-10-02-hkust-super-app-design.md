## 1. 共同理解与决定状态

### 用户已确认

1. 一个 App 同时服务学习、校园生活、社交与活动组织。
2. 学校信息与基础服务保持完整，不能因扩大社交范围而降为附属内容。
3. HKUST 是已有项目与初始资源所在，长期社交覆盖全香港，可以发展多校场景。
4. 校园墙面向在校学生交流；与毕业校友目录是不同产品需求。
5. 给不容易主动融入的人清楚、温和的参与方式；社交自愿，允许安静浏览与独自使用。
6. 参与者和普通活动组织者都需要被服务。
7. 先做好整体规划，检查现有成果，再替换不符合定位的旧功能。

### 本版推荐，尚不当作已批准

- 首试建议做深 HKUST，同时允许符合公开活动条件的校外用户参加；其他学校先提供城市社交与手动学习管理，按学校逐个接入。已向用户询问首试范围，未回复时将此保留为可调整建议。
- 学习由课程与截止、资料与笔记、学习协作三层组成；资料 AI 问答与自动复习作为后续验证项。
- 学生使用五入口；城市用户使用今天、发现、消息、我的，公共校园信息可搜索。使用情境由本人选择，不能由邮箱或定位悄悄切换。
- 复用现有 Web 工程做手机优先的首试客户端；正式手机 App 的分发与后台能力单独验收。
- 基础学习、生活、社交免费；组织者高级工具、付费活动与合作收入后续验证。

### 判断成功

学生更容易找到并处理校园事务；学习资料与安排在同一处可找；愿意参与的人能加入预期清楚的活动；组织者能持续办活动。纯工具用户、内容浏览者与不建立好友关系的人都可以得到完整价值。

## 2. 产品定位、边界与取舍

**定位：以校园学习和生活为基础，连接香港兴趣、活动与真实关系的 Super App。**

体验承诺：打开它，知道今天该做什么；想学习或参加活动时，资料、服务和同伴都能找到。

比较过的路径：

| 路径 | 长处 | 取舍 | 判断 |
| --- | --- | --- | --- |
| 校园日常做深、共享全港社交与组织能力 | 有明确的日常用途，可延续校内关系到跨校及城市 | 要同时做好数据和运营；需按学校逐步接入 | 推荐，符合已确认目标 |
| 全港活动平台先行，学校仅是用户来源 | 活动定位集中，学校接口依赖较少 | 学习与校园生活主干会被削弱 | 不作为本版主路线 |
| 同时复制所有城市生活、交易和学校系统 | 想象范围很大 | 来源、交易和运营负担远超已验证需求 | 保留场景扩展能力，逐项评估 |

本产品不宣称包办香港所有事务。学校服务、学习管理、社区和活动是完整目标；外卖履约、银行钱包、即时打车、酒店预订等没有进入本版核心范围。原系统的正式选课、成绩、提交与审批是否内置，取决于实际权限与单独设计。

## 3. 用户、核心任务与价值

| 用户 | 核心任务 | 关键结果 |
| --- | --- | --- |
| UG、TPG、RPG、交换生 | 管理课表、截止、资料、校园事务 | 查找与处理更快，不漏掉与自己有关的变化 |
| 新生与刚来港的人 | 找入口、了解流程、第一次参加活动 | 知道下一步怎么做、到场找谁 |
| 习惯安静的人 | 自己学习，必要时找同伴 | 参与预期清楚，可以拒绝、退出或不社交 |
| 学习与项目组成员 | 找角色、对齐时间、分享资料、跟进任务 | 组队与协作有持续空间 |
| 城市活动参与者 | 找近期可参加的活动和稳定圈子 | 活动实际可加入，体验与描述一致 |
| 普通组织者、社团、兴趣社群 | 招募、报名、通知、成行、再办一场 | 减少重复协调，形成稳定参与 |
| 毕业生 | 保留自建资料、日程和自愿形成的关系 | 校园资格变化不破坏个人账户和城市使用 |
| 校园内容及平台运营者 | 维护来源、组织活动、处理举报 | 工作可追踪，职责清楚 |

初始学校范围为 HKUST 清水湾；广州校区及其他学校需独立登记，不能共用清水湾时刻、规则和地点数据。地域筛选、成员身份、内容可见范围是三种不同条件。

## 4. 产品气质与体验原则

界面让用户感觉清楚、有生活感、可以放心迈出第一步。学习页面强调信息层级，内容与活动页面呈现真实日常。建议浅色底、深色正文、少量强调色与真实场景照片；具体视觉稿另行评审，本文件不把文字方向视作最终 UI。

用户既可以当天处理一项截止，也可以慢慢熟悉一个圈子。产品不以刷时长或发帖频率衡量所有人的成功。

- 首页先呈现本人事项与相关变化；发现页承接探索。
- 不强制头像、MBTI、自我介绍、通讯录或精确定位。
- 社交建议由本人选择开启；学习和服务不以参与社区为门槛。
- 课程、邮件、收藏、参加历史默认私有；发布或共享时明确选范围。
- 官方资料、平台整理与学生经验有不同标识。
- 不制造人气、报名人数、实时状态和组织者身份。
- 人数、时长与交流强度按活动测试，不把内向者视为同一种用户。

## 5. 信息架构与首次使用

### 学生端五入口

| 入口 | 核心页面 | 负责的问题 |
| --- | --- | --- |
| 今天 | 今日概览、周日程、待办、重要变化、常用入口 | 我的时间和事项怎样安排？ |
| 校园 | 学习、生活服务、学校公告、活动机会、新生办事 | 这所学校里的事在哪里找、怎么办？ |
| 发现 | 动态、一起、圈子；同校/跨校/全港范围；活动/圈子/组织者详情 | 我可以看什么、参与什么、和谁做事情？ |
| 消息 | 通知、互动、请求、会话 | 哪些变化与回复需要处理？ |
| 我的 | 身份、资料、收藏、参与、发布、连接、数据覆盖、设置 | 我的内容、关系与权限是什么？ |

校园墙作为发现页的“同校动态”存在，校园页提供直达入口，底层是同一组内容。学习组、课程讨论和一般兴趣圈子共享社区能力，但权限、模板与内容类型不同。

城市用户默认四入口：今天、发现、消息、我的；今天保留个人日程与已参加活动。选择“学校生活”后显示校园入口，未验证者只读公共校园资料。设置中随时改使用情境，不影响权限核验，不要求两个账户。

### 首次打开

1. 可以先查公共校园信息或看公开活动，无需先填长问卷。
2. 选择学校生活或香港活动、常用语言与希望浏览的范围；允许跳过。
3. 保存跨设备内容时建立账户；访问学校成员内容时完成相应资格核验。
4. 添加一项日程、导入课表、收藏活动或关注一个圈子，任一都可成为首个有用动作。
5. 个人数据连接、社交兴趣和通知分开选择，不捆绑授权。

用户没有课程时显示添加日程的入口；没有社交兴趣时正常使用学习生活；没有活动供给时显示真实缺口和后续订阅选择。

## 6. 今天：把学习、生活和活动放在同一日程

首页区块按本人任务组织：下一项日程 → 需要处理 → 已关注事项的重要变化 → 常用服务 → 完整日程。选择开启社交建议后，可出现至多一张可关闭的建议卡。

课程、作业截止、个人待办、正式预约和活动报名是不同对象。它们可以共同展示，不混淆来源或完成状态。完成个人任务不会自动表示已在学校交作业；保存官方报名链接也不能表示报名成功。

| 内容 | 关键操作 | 必须处理的异常 |
| --- | --- | --- |
| 课程与事件 | 查看、路线、相关通知、冲突检查 | 取消、改期、时区与重复课程例外 |
| 截止与待办 | 核对原文、确认日期、分步任务、完成、延后 | 日期不明确、已过期、来源变更 |
| 预约与活动 | 看条件、集合说明、修改/退出入口 | 候补、待审核、已取消、外部状态未知 |
| 常用校园服务 | 置顶、查车、地点与办理 | 过期、同步失败、部分覆盖 |

支持手动安排、ICS 导入与获准同步。日历保留开始/结束、全天语义、来源时区、重复与例外；用户必须看到导入预览和跳过原因。不能把重复课只导成第一节后仍显示全部成功。

日程检查仅在个人空间内进行。用户可主动按空闲时间找活动；对其他人只共享本人选择的可用时段，不泄露整张课表。该时段协商功能可后续交付，首试用自选时间。

## 7. 学习：安排、资料、协作三层

### 课程与学习安排

每门课有独立页面，集合经授权的课程信息、课表、通知、作业/考试、相关资料入口、个人笔记和讨论。正式选课状态与用户自行关注课程分开。课程评价与同学经验标明作者身份层级、学期和适用背景，不混为官方结论。

选课辅助保留课程组合与冲突检查；学分、先修及毕业要求必须引用当前规则，未接通正式学籍就显示辅助规划。导师、成绩或研究数据的私人接入另行核验，不能从课程名称推断。

### 资料与笔记

首试支持课程资料链接、个人笔记、附件归档和标题/标签查找；用户能给资料关联课程、任务与复习时间。个人上传默认私有，主动共享到学习组时明确成员范围。公开社区不自动获得课程资料访问权。

完整阶段增加阅读标注、资料版本、章节关联和复习清单。全文检索、文档解析与 AI 问答分开验收；原文打不开或解析不完整时不能声称已读完整资料。

AI 学习辅助建议放在对应资料/课程内：解释概念、按资料回答、生成待核对的复习提纲或练习。回答返回页码/段落依据；无证据时说明缺口；用户可编辑与删除生成内容。处理范围、第三方处理方式与用量应在启用时清楚说明。它是后续建议项，不能替代基础学习功能。

### 学习协作

课程讨论支持问题、答案和已解决状态。学习组支持成员、简单任务、资料链接、讨论与时间安排。项目招募写清目标、角色、必要技能、工作语言、预计投入和截止，用户主动申请并选择共享信息。

“共同选课”“收藏课程”“加入课程圈子”不相互推定；用户私有学籍、成绩和课表不出现在陌生人的搜索或推荐理由里。

## 8. 校园生活：完整服务范围

| 场景 | 完整范围 | 交付边界 |
| --- | --- | --- |
| 交通 | 学校大巴/班车、公共巴士与小巴、站点、运行日、时刻、票价、末班与变更 | 实时 ETA 按线路核验；无实时源显示计划时刻 |
| 地图 | 教室、楼宇、楼层、入口、车站、设施与服务点 | 路线和无障碍信息带依据，不能推算未知开放通道 |
| 餐饮与商店 | 位置、营业时间、菜单/价格来源、优惠、学生体验 | 评价标日期；不伪造排队人数 |
| 图书馆与自习 | 空间、开放、规则、预约入口和已接通的可用状态 | 点击外部预约不等于预约成功 |
| 体育与设施 | 场地、设备、费用、规则、预约及个人安排 | 支付、配额和资格按真实接口处理 |
| 住宿与生活 | 公告、洗衣、打印、报修、包裹、常用服务 | 无接口时提供说明与办理入口，不能显示虚假实时状态 |
| 活动与机会 | 讲座、社团、比赛、义工、招聘、奖学金、交换与研究机会 | 资格、截止、主办方和原文可核对 |
| 健康与支持 | 校园健康、辅导和学生支持的官方入口 | 显示当前服务资料，不推断个人健康状态 |
| 新生 | UG/TPG/RPG/交换与生活情境对应的清单 | 明确材料、时间、地点、完成状态与来源 |
| 天气与校园变化 | 有来源的天气、交通变化与校方公告 | 平台天气判断不代替学校正式停课决定 |

所有服务详情统一为：适用人群、时间地点、所需材料、费用条件、办理步骤、原文与更新时间。后续多校接入复用结构，每所学校分别核验资料。

## 9. 发现：同校、跨校、全港的内容与活动

“动态 / 一起 / 圈子”是内容类型，“同校 / 跨校 / 全港”是浏览范围。改变浏览范围不会改变原有内容的访问权限，也不会将旧校园帖子自动公开。

动态涵盖日常图文、经验、求助、失物、二手和项目招募。帖子有草稿、发布、编辑、删除、回复、收藏、举报、屏蔽；求助可解决，失物可找回，二手可售出，招募可满员/结束。

同校动态默认对该学校有有效成员资格的人可见。全港社区动态默认对已注册且符合社区条件的用户可见；组织者主动公开的活动介绍可面向网页访客。公开互联网、平台注册成员、学校成员、圈子成员、特定参与者与仅本人是不同访问范围。

用户可选最新、关注与分类。相关性推荐优先可参与性、所选兴趣和真实更新时间，不以争议、人气或敏感画像主导。低供给时说明当前筛选无结果，再由用户扩大日期、地区或活动类型，不偷偷改变语言和资格条件。

## 10. 社交参与：减少不明确的期待

活动供给同时包含真实组织者的固定活动与用户自发邀约。第一次参加者可以加入已安排好的事情，不必先成为发起人。

活动类型包括安静共处、吃饭/运动等日常同伴、官方活动同行、学习与项目协作、定期兴趣小聚。时长、人数、一对一或小组结构按场景验证；不按 MBTI 预设最佳配置。

活动卡必需信息：具体内容、开始/结束、地点与到达说明、人数与名额、语言、费用、能力/资格要求、组织者、报名截止、审核方式、集合与取消规则。明确是否欢迎首次参加、组织者是否在场、交流方式和未成团处理。场地使用与校园入场资格须由组织者核实。

| 用户动作 | 状态与规则 |
| --- | --- |
| 收藏 | 私人兴趣，不占名额、不通知陌生人 |
| 普通报名 | 名额允许并满足条件后明确进入已加入 |
| 审核申请 | 申请中与已加入不同；只收必要资料 |
| 候补 | 用户主动选择；有空位后在展示的期限内确认，不自动承担出席承诺 |
| 退出 | 释放名额，按已展示规则处理；不强制公开原因 |
| 改期/改地点/改费用 | 通知受影响者；重大变化需重新确认，拒绝可退出 |
| 活动结束 | 查看自愿分享的总结、反馈、下一场或联系申请 |

服务端处理并发名额与重复报名，页面计数不作为准入依据。未成团、无人回应、取消与未获通过给出清楚状态；不公开社交信用分或缺席排行榜。恶意占位与骚扰按透明、有申诉的规则处理。

首试平台内自发活动以免费为主；外部付费活动可以展示明确费用和官方办理入口。平台内收款、退款和争议处理作为独立后续单元，不先做余额钱包。

## 11. 圈子、关系与组织者

### 圈子与关系

圈子展示主题、适合谁、语言、规则、负责者、近期内容、下一场已确认活动与新人参与说明。关注更新、加入成员空间、报名某一场活动分别选择。

活动临时讨论在结束 24 小时后转为只读，这一建议规则在报名页预先说明；需要持续讨论可自愿加入圈子。普通联系人需要双方同意，不因同场活动自动加好友、加永久群或共享联系方式。聊天只读不等于删除历史，存储和删除按用户可见的数据政策执行。

默认不显示在线状态或已读回执。陌生私信进入请求箱；屏蔽覆盖内容、私信、主页和推荐。被屏蔽者与用户同时报名活动时，由受限的后台流程协助处理，不泄露举报与屏蔽原因。

### 组织者工作台

普通用户、学生社团、城市兴趣组织共用核心工具，组织身份与个人身份可区分。组织者不是默认可信认证；页面显示实际核验层级。

基本流程：选择模板 → 填写事项与参与条件 → 确认地点/责任 → 预览发布 → 审核/候补/名单 → 集合与变更 → 结束与总结 → 复制下一场。

首试含名额、申请、参与者必要信息、通知、取消和结束；完整阶段增加系列活动、多个管理员与角色、报名问题模板、资源/场地协作、付费能力及社群经营数据。通知仅发给该事项的合适受众，不能把报名名单自动变成营销名单。

组织者能看到实际报名、候补、取消与自愿确认出席，不可读参与者私人课表、邮箱正文或其他圈子的参加历史。经营数据聚合呈现；一次举办记录不自动生成未经核验的“优质认证”。

| 场景 | 连续操作 | 不可混淆的结果 |

| 上课出行 | 今天课程 → 地点 → 班车/路线 → 课程变化 | 计划时刻与实时到站不同 |

| 学习组队 | 课程 → 主动发招募 → 申请/选择 → 学习组 → 资料/任务/讨论 | 不公开课程资格、成绩或完整课表 |
| 官方活动与同行 | 活动资格 → 冲突检查 → 官方报名 → 日程 → 可选同行 | 同行成功不等于取得官方入场资格 |

## 13. 数据来源、接入与可信度

已有来源清单不等于已接通。每项能力标记“已同步 / 已导入 / 官方办理 / 暂未覆盖或异常”，并说明具体范围。

合作 API 或获准接口优先；公开资料按允许的方式结构化整理。私人邮箱和学校记录要求逐用户授权。旧开发环境的单个令牌不能用作全体学生的连接；不能通过读取邮件主题声称已提取完整作业正文。

每条数据保留来源、原文、发布者、适用学校/人群、有效时间、采集时间、最近成功核验、权限范围、状态与版本。校园资格、活动地点、信息发布者不能仅凭名称相似合并。

同步流程：获取 → 结构化 → 保存证据与版本 → 保守去重 → 受众/时效检查 → 按权限检索 → 更新相关日程与提醒。来源 ID、规范链接、时间地点等支持去重；标题相似不直接合并。冲突与低置信度关键日期展示给用户核对。

空结果、未授权、部分覆盖、过期、同步失败与授权撤销分别呈现。过期 ETA 停止倒数；过期时刻表不得用于今天的下一班推算；取消的活动不得继续发集合提醒。

## 14. 搜索、消息与 AI 的位置

搜索覆盖当前用户有权读的课程、服务、地点、活动、帖子、圈子、日程与个人资料。支持中英文名称、别名与课程代码；分类、日期、地区、语言和来源筛选可组合。城市或学校的筛选不能绕过访问权限。

消息分为个人安排与校园通知、社区互动、陌生联系请求、已同意会话。活动变更与普通推荐分开；用户控制静默时段、提醒频率与订阅。重要提醒也不能承诺在未授权或不可用的系统通道必达。

AI 建议用于有证据的搜索说明、用户主动选择的学习资料解释、待核对的日期整理、组织者活动草稿。每项生成保留来源或标明草稿，需要实际发布的操作由本人完成。AI 不擅自报名、加群、代发消息或对外公开私人资料。

## 15. 身份、范围与数据生命周期

一个人一个主账户，可关联多个学校/组织资格。公开昵称、认证联系渠道、学校成员资格和公开显示的个人资料分开存储。控制学校邮箱不等于在籍核验；邀请试点和正式身份方案分别登记。

访问范围由资源所属组织、可见级别、成员资格、报名状态及当前用户共同决定。服务端、检索、缓存、导出与通知预览使用一致的规则。公开地区筛选和“同校”推荐不是安全边界。

访客能看公开记录；城市注册用户参与符合条件的公共活动；学校成员读校内内容；组织者管理本活动；审核员按职责处理社区事件。管理后台不默认获得个人邮件或学习文件。

断开来源停止同步并清除令牌，用户选择保留已导入副本或删除该来源记录与派生提醒；自建笔记独立处理。退出学校不会删除个人主账户，机构受限资料的访问按资格与来源条件调整。删除账户须说明日程、文件、公开内容、群组记录及必要审计的处理，能撤销的操作与最终删除分开。

首试城市陌生人活动建议面向成年人；若要纳入未成年参与者，需要独立的年龄、组织责任与参与设计。该建议不是法律结论，也不用于推断学校用户年龄。

## 16. 运营与冷启动

数据、内容、活动和审核各有负责人；可以兼任，不能缺位。校园功能在社区为空时仍可用。社交起步依靠真实活动与组织者，不能要求所有新人先发起。

首试建议做深 HKUST，并提供少量对校外开放、资格明确的活动。校内专属活动明确入场条件；跨校用户不能因为平台报名就获得校园通行权。其他学校的需求先登记，再逐校验证来源和组织资源。

探索性研究建议至少 8 人做信息与学习任务测试；社交与组织试点建议 18–24 位自愿参与者、3–4 位真实组织者，连续两周。人数与周期是可调整建议，不代表统计证明。先比较安静学习、活动同行、项目组队等具体用途。

运营工作台包括：来源健康/过期/冲突；公告与服务修正；活动名额与状态；组织身份；举报/申诉；通知异常；数据质量与访问审计。涉嫌冒名、骚扰、曝光私人资料等有受限证据与处理流程；审核熟人事件时回避。

每一场准备活动说明、集合点、主持责任、未成团和取消规则、结束处理。反馈自愿，出席确认不要求持续定位或拍照；不制造用户、动态、报名与活动成功率。

扩校/扩区的依据是能持续维护来源、有真实组织者、能处理基本支持，以及重复参与的证据。下载量或一场大型活动不单独触发扩张。

## 17. 可独立交付的八个单元

这些是逻辑和验收边界，不要求拆成八个服务或项目。建议先在现有应用内保持清楚模块边界，按用户流程逐步交付。

| 单元 | 职责与输出 | 依赖 |
| --- | --- | --- |
| U0 身份与我的一天 | 账户、情境、成员资格、私有日程/待办、手动/ICS 导入、基础今天 | 基础存储与验证方式；详见独立规格 |
| U1 来源与个人连接 | 来源登记、同步版本、逐用户授权、覆盖和失败状态 | U0 权限边界；外部接入条件 |
| U2 学习空间 | 课程、资料/笔记、复习安排、学习组与项目任务 | U0；授权记录来自 U1；社区协作复用 U4 |
| U3 校园生活 | 地点、交通、设施、服务、新生与机会 | U1 公共数据；私有预约依赖授权 |

| U7 运营与质量 | 数据维护、审核、支持、观测、审计与试点指标 | 从首个真实数据或 UGC 模块起随之交付 |

U0 先建立一个真实可用的个人日常流程；U1/U3 与 U4/U5 的设计和验证可并行推进。这里的并行指项目工作流，不表示本会话自动使用子代理。

共用对象包含 Account、Institution、Membership、Source、SourceRecord、Connection、Course、StudyResource、Note、Task、CalendarEvent、Place、Service、Route、Post、Circle、Activity、Participation、ContactRequest、Notification、Report。所有记录保留稳定 ID、所属范围、来源和生命周期；任务与事件、正式校园活动与同行活动分别建模。

报名名额及状态变更使用事务和幂等约束，变更后再可靠触发通知/索引。私有数据不能通过日志、搜索摘要或通知预览泄露。具体数据库、认证厂商、托管和消息通道在模块实施计划中选定，本阶段不安装依赖或配置外部服务。

## 19. 完整范围、交付阶段与承诺

### 首试必须同时成立的三个流程

A. 学习：添加/导入课程与事项 → 今天/周日程 → 课程资料或笔记 → 提醒/状态更新。

B. 生活：找到真实校园信息 → 核对来源与条件 → 找地点/路线或办理 → 保存安排。

C. 社交：真实组织者发布 → 用户看懂条件 → 报名/候补/退出 → 变更与集合 → 结束/自选再次参加。

首试包含基本资料与笔记、校园墙、求助、简单圈子、学习招募与活动组织，不等所有学校接口开放后才验证社交。未接入的个人或实时能力明确列为未完成；完成首试不等于完整 Super App 已完成。

| 阶段 | 可交付结果 | 通过条件 |
| --- | --- | --- |
| 当前设计 | 总体方案、范围验收清单、U0 首单元规格、已有调研 | 用户审阅书面规格 |
| 接入与体验核验 | 来源覆盖、身份方案、任务基线、关键流程原型、真实主持资源 | 数据与体验风险可具体处理；原型示例标明 |
| 第一轮可用产品 | A/B/C 三条真实流程及基本运营 | 能用真实数据、真实账户和真实活动验收 |
| 完整 HKUST 深化 | 授权学习数据、更完整资料功能、实时/预约覆盖、社群与组织工具 | 逐项清除范围清单中的缺口 |
| 多校与全港扩展 | 新校来源与资格、城市用户路径、更多组织者和稳定活动 | 权限不串校，运营供给和支持可持续 |
| 客户端与发布准备 | 原生/安装形态、通知可靠性、无障碍、恢复、支持和用户数据生命周期 | 完成对应渠道与范围的真实验收 |

没有已确认的团队容量、接口审批周期和预算，当前不写确定上线日期。可控开发、来源等待与运营验证分别估算，不能用一个总周数掩盖外部依赖。下一步是逐模块实施计划，而不是把本总体蓝图一次性变成巨大开发任务。

## 20. 研究、指标与失败后的动作

| 假设 | 验证方法 | 发现问题后怎样调整 |
| --- | --- | --- |
| 汇总能减少查找负担 | 相同核心任务与原流程对照；完成率、时间、跳转、错误 | 补来源和检索分类，不能靠首页多放入口解决 |
| 学习功能有独立价值 | 观察课表、资料、笔记、任务的实际使用与失败 | 减少重复录入，修正课程与资料组织 |
| 初次参加更容易 | 检查用户能否解释地点、接应、语言、费用、退出 | 调整活动说明和主持方式，保留不想参加的选择 |
| 圈子带来自愿重复参与 | 分场景记录再次参加与反馈 | 调整频率、内容和主持，不用催促补指标 |
| 组织者愿意持续办 | 记录筹备耗时、协调次数、成行/取消和复办 | 优先补阻力最大的组织工具 |
| 能从校内扩到城市 | 看用户实际跨范围参与和组织者供给 | 先做强有供给的地区/类型，不用伪造密度填空 |

可用性暂定目标：至少 8 名不同学制和生活情境用户，核心任务完成率目标 ≥90%，中位用时较原流程减少 ≥30%。这是待验证目标，报告给出人数与任务分母，不能当现成绩。

两周社交试点建立基线，分别记录看到、收藏、申请、加入、确认出席、再次参加、反馈的分母及失联/取消原因。实际出席用自愿确认，反馈缺失不算满意。留存看有需要时是否回来，不要求所有用户天天社交；短期结果不宣称治疗孤独或证明友谊。

质量另有硬性验收：固定测试样本中的日期、来源、权限、重复导入、并发名额和取消处理应符合规格；严重越权、关键日期错误或假状态未解决时不放大试用范围。

## 21. 维护、商业与控制范围

成本记录到来源维护、文件存储/处理、消息、AI 用量、审核、主持与支持。首期建议基本学习生活和基础社交免费；长期可验证组织者高级工具、合适的活动服务费与清楚标识的校园/场地合作。没有依据时不设置付费转化率或收入预测。

广告和合作内容不能购买作业截止/官方通知的优先级；个人课表、邮件和关系数据不出售。AI 有用量边界和明确选择，不把每次页面刷新变成付费模型调用。

暂不做外貌滑卡、强制人格测评、社交人气排名、实时人员地图、自动通讯录导入、无限短视频/直播、平台余额钱包。后续引入任何一项，都需要说明它解决了哪个已验证问题。
