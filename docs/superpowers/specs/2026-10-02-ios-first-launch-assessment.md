# iOS 首发与官网分工评估

日期：2026-10-02。已确认：先做 iOS，安卓客户端暂不做。其余范围和技术选型为建议；本轮只评估，没有创建移动项目或外部账户。

后续范围决定：用户已要求将参考网站全部功能放入[长期路线图](2026-10-02-bnbu-full-feature-roadmap.md)。iPad/Mac/Watch 与 AI/深度校园功能已保留，Android/Windows 为暂缓平台；下文首版建议不等于删除这些长期能力。完整能力增加后，React Native/Expo 对 Widget/Live Activities/Watch 的原生扩展成本需在选型验证中检查，不能按复用网页的工作量估算。

## 当前基础

本轮检查的 package.json 显示，仓库已有 TypeScript MCP/core 与 Next.js/React Hub；没有发现现成的 Swift 或 Expo 客户端工程。已完成的数据核查、API 合同和参考规则测试可复用，但不能等同于已实现的用户后端或移动 App。

既有[API 文档](../../api/super-app-api.md)以浏览器服务器会话为首期假设。iOS 需要单独补充原生认证、回调、设备凭证、通知与分享链接设计，不能把浏览器 Cookie/CSRF 方案原样作为原生认证方案。

## 路线选择

| 路线 | 优点 | 主要代价 | 判断 |
| --- | --- | --- | --- |
| 完整网页版先上线，再开发 iOS | 链接试用方便，较快观察网页使用 | 学生主界面会做两轮；网页留存不能直接推定手机 App 留存 | 当目标尚不确定或缺少移动开发能力时可选，当前不优先 |
| 只做 iOS，没有可浏览的分享页 | 学生端交付集中 | 活动邀请接收者需要先安装，组织者招募及跨设备分享受限 | 不推荐 |
| iOS 主产品＋轻量官网/分享页＋最小运营后台 | 集中打磨日常使用，同时保留低门槛传播与内容维护 | 仍需定义几个网页端边界，共用账户和后端 | 推荐 |

官网可以先发布，但它不应成为 iOS 开发的串行前置大项目。先验证核心手机流程，官网与后端配套推进。

## 三端各做什么

- iOS：今天安排、日程/任务、校园服务、交通、活动/学习招募、本人参与状态与必要提醒。
- 官网及分享页：产品说明、真实功能预览、内测/下载入口、公开活动详情、支持与隐私说明。校园受限活动不公开成员、完整地址或内部内容；已安装用户可进入对应 App 页面，未安装用户可先理解活动再决定安装。
- 运营后台：核验校巴时刻版本、更新失效服务链接、管理组织者/活动、处理举报和封禁。初期只服务少数运营人员。

安卓浏览器可查看公开分享内容，但不等同于提供安卓 App 或完整网页版；本轮不安排安卓开发、适配或发版。

## 首版产品范围

保留“学习＋生活＋温和社交”的完整价值链，用较少真实场景做深：

1. 学习：手动安排/获准 ICS 导入、任务、今天与提醒；未接通 Canvas/SIS 时如实说明。
2. 生活：少量高频路线的可靠时刻/公开到站信息、常用校园服务及来源更新时间。
3. 社交：有真实组织者的小型活动与学习招募，清楚展示时间、人数、语言、地点和参与要求；完成报名/候补/退出/变更通知。一般用户可发结构化招募，配套审核和举报。
4. 身份：平台账号、学校资格、私人来源授权分开；公共查车/公开活动不强制注册，保存和参与时再登录。

首版不以无限信息流、随机匿名私聊、全量聊天系统、支付或未批准学校接口作为上线前置。校园墙的广泛内容形态后续扩展；小型招募已经承担初始社交入口。活动通知和联系组织者的路径必须可用，不能只提供静态海报。

## 技术建议及 API 缺口

在现有 React/TypeScript 基础、小团队推进的假设下，推荐 React Native＋Expo 制作 iOS 客户端，继续使用 Next.js 承担官网与管理页，后端统一账户和业务数据。可以复用类型、接口客户端及部分规则；Next.js 页面不能直接变成原生界面。此次不确定托管服务、供应商或套餐。

如果后续团队以熟练 Swift 开发者为主，或产品主要价值转向复杂苹果系统集成，则应重新评估 SwiftUI。选择跨平台框架不意味着现在要交付安卓。

实施前补充以下合同，并验证一个 iPhone 上可用的贯通流程：

- 原生授权使用系统认证会话、批准回调、state/nonce/PKCE；平台会话与学校/Graph/Canvas Token 分离。敏感设备凭证存 Keychain；学校连接密钥仍由获准后端持有。
- 设备会话、刷新/撤销、丢失设备退出；多账号切换清理私人缓存。
- APNs 设备注册、通知类别/偏好/撤销、活动改期提醒；不承诺所有通知必达。
- 活动和邀请链接打开指定页面，未安装/未登录/无权限有明确行为。
- 文件导入、时区、弱网/离线状态、动态字体及真机验收。
- 账户删除、内容举报/屏蔽、审核人员工作流。

## 可验收推进阶段

| 阶段 | 交付与继续条件 |
| --- | --- |
| 手机流程验证 | 可点击关键页面；建议找 5–8 位目标学生观察查车、安排学习、参加小活动，包含不习惯主动社交的学生；修复明显理解障碍 |
| iOS 贯通版本 | 真机完成注册→保存安排→重新登录仍可见→查询真实交通→报名真实活动→收到状态变化；两个账户权限隔离通过；同时具备必要后台与官网 |
| TestFlight 小范围内测 | 建议招募 30–50 位真实学生和 3–5 位组织者，观察至少两个正常教学周；人数与观察期是建议，不是行业基准或已招募成果 |
| App Store 首发 | 核心流程稳定、持续有真实活动、有人维护数据及处理举报；隐私/删除/支持和审核访问就绪，再提交审核 |

观察用户是否在不同日期主动回来、学习与交通功能的实际使用、从查看活动到报名再到真实到场的变化，以及取消/爽约原因。到场只能来自用户同意下的签到或组织者核实，不能用点击/报名代替。小样本用于发现问题，不宣称证明全港市场成立。具体成功阈值在试验开始前另定，不能看到结果后调整口径。

## 苹果发行条件核查

- Apple Developer Program 官方标价每年 99 美元，地区价格以注册时为准；个人账户显示个人法定姓名，组织账户需合法实体及相应核验。参见[注册要求](https://developer.apple.com/programs/enroll/)。用户尚未选择主体，未创建或购买账号。
- TestFlight 支持外部测试，首个外测版本需要审核；先少量试用再公开上架。参见[TestFlight](https://developer.apple.com/testflight/)。
- App 应有实质使用价值，不能只是网站/链接集合；社交内容需过滤、举报、屏蔽和联系渠道；支持注册时需提供 App 内账号删除。参见[审核指南 4.2、1.2、5.1.1](https://developer.apple.com/app-store/review/guidelines/)。
- 登录方式需按实际账户体系评估 4.8；学校场景有特定例外，不自动适用于扩展到全港城市用户的所有登录。Sign in with Apple 可作为产品选项，不能将 Apple 隐藏邮箱当学生资格，也不能据邮箱相同自动合并账户。
