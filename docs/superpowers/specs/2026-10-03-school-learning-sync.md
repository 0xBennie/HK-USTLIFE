# 学习安排：授权后自动同步为主，文件导入为备用

2026-10-03 用户明确纠正：连接用户Canvas之后应自动出现学习信息，不应让日常使用依赖手动导入课表。本决定覆盖此前将ICS作为首版主要数据入口的排序；不删除已经实现的备用导入能力。

## 已核验的来源分工

- HKUST CEI [学生FAQ](https://cei.hkust.edu.hk/en-hk/alh-and-edtech/faqs-students)明确说明Canvas Calendar只显示Canvas课程作业和事件，正式课表在SIS。FAQ同时提示并非所有课程使用Canvas，课程是否发布取决于教师。
- Academic Registry [查看本人课表](https://registry.hkust.edu.hk/resource-library/how-can-i-view-my-time-table-my-enrollment-student-center)说明Student Center中的Class Schedule提供列表和周历。
- Canvas [Calendar Events API](https://developerdocs.instructure.com/services/canvas/resources/calendar_events)可读取事件和assignment类型；[OAuth2文档](https://canvas.instructure.com/doc/api/file.oauth.html)要求相应Developer Key/授权配置。接口存在不代表本项目已获学校批准。

因此不能承诺“只连Canvas就有完整正式课表”。产品应提供统一的学校连接设置，在合法获准的前提下汇总Canvas课程/作业截止/课程事件与SIS正式课表；两者连接状态和覆盖范围独立显示。不要要求用户在不同模块重复整理同一份数据。

## 目标用户流程（尚未实现）

1. 用户点击“使用 HKUST 账号登录”，通过系统认证浏览器进入学校官方登录页，输入学校账号密码并按学校要求完成MFA；平台不收取学校密码。
2. 在学校批准接入的前提下，用户确认SIS课表读取用途，系统自动开始首次同步，正式课表进入今天/周课表，不要求再上传ICS。是否存在学校提供的逐用户授权页、能否复用登录会话，仍需校方确认；产品内同意不能替代学校数据权限。
3. Canvas作为补充连接，同步课程作业与事件；需要单独授权时明确说明。每个来源显示独立状态，未接通SIS标“正式课表未同步”，不能把空白Canvas日历解释为无课。
4. 用户在同一“今天/周课表”查看有来源区分的课程安排、DDL、课程事件和个人事项。只有有明确匹配依据时合并跨来源课程，不用名称相似猜测关联。
5. 后续自动同步与手动刷新更新来源变更，显示上次成功时间、部分覆盖和错误。具体后台刷新频率需按获批接口限额与iOS运行方式验证，不承诺实时。
6. 个人笔记、提醒偏好和本地任务完成状态独立保留，不覆盖学校数据，不把本地完成解释为Canvas提交。撤销授权停止同步，私人数据保留/删除按用户明确选择处理。

ICS文件选择、导入预览和手动添加继续提供，作为连接不可用或用户自有日历的备用路径，不作为自动连接成功的证明。

## 当前事实与所需条件

- `src/product/auth.ts`返回`connections.canvas=approval_required`。原生平台登录是本地开发登录，不等于Canvas授权。
- 当前没有完成学校OAuth回调、令牌保管/更新、真实课程/作业/事件同步，也没有正式SIS课表连接。不得在UI显示“已连接”或给出假连接按钮。
- 需要获批Canvas应用配置、权限范围与回调；正式课表还需核验SIS获准接入方式和字段。当前不申请外部账户、不发送申请邮件、不访问私人学校账号。
- 原生学习页本次只明确数据来源缺口、把ICS入口标为备用；不是自动同步的实现交付。

## 追加验收，不能由ICS或mock抵扣

- 在获准环境完成真实用户授权→首次自动同步→学习页出现对应数据，保留脱敏证据。
- 证明课程列表、作业截止、Canvas事件和正式课表各自的来源与覆盖；没有事件的课程不能推断为没课。
- 源端新增/修改/取消和课程权限变化可正确更新；多页、部分失败、过期授权和重试不制造重复或伪造空结果。
- 跨账户隔离，退出/撤销授权后不继续展示另一人的数据；私人笔记/完成状态不会被学校同步覆盖。
- iOS上的登录返回、首次加载、后续刷新和提醒更新需实际验证。

现有Goal的本地MVP记录继续保留；自动学校同步仍是明确未完成的用户核心要求，不因原有后端和ICS测试通过而降级为已交付。

## HKUST登录与SIS接入决定（2026-10-03追加）

用户进一步明确：主要入口为同学自己的HKUST账号登录，并授权SIS。另建平台密码、手动导入不应成为此主流程的额外必经步骤。登录后只在拥有明确授权时读取本人课表；社交参与保持自愿，私人课表不向其他学生公开。

需要分别取得ITSO批准的应用登录配置，以及SIS系统/数据拥有者批准的数据访问方式与字段。学生授权不能代替学校批准。具体申请问题、拟议实现及测试清单见[HKUST登录及SIS接入](../../api/hkust-sis-integration.md)。
