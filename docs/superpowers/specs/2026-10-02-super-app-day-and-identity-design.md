# U0：身份与我的一天——首个可独立交付单元设计

日期：2026-10-02｜状态：供用户审阅的子系统规格，未实施。

依据：[总体设计](2026-10-02-hkust-super-app-design.md)；范围对应 A01–A06，验证对应 T01–T03、T10–T11。这里写的是行为与模块边界，不是代码实施计划。

## 1. 目标与范围

让用户拥有自己的账户、使用情境和可持续保存的安排：添加或导入日程 → 在今天/周日程看清楚 → 编辑个人任务 → 处理变化。为学校服务和全港社交提供相同身份与权限基础。

包含：主账户、公开资料与私有偏好分离、学校/城市情境、成员资格状态、个人事件/任务、ICS 预览与保存、重复导入、今日视图、提醒计划、错误状态和数据操作。

此单元不单独交付学校正式接口、社区发帖、活动报名或 AI 学习；它们通过约定对象接入。完成 U0 只表示个人安排基础可用，不表示首个完整 Super App 已交付。

## 2. 用户和权限

访客可看公共入口；建立账户后保存个人事项。用户可以选择学校情境并查看公共学校信息，但成员资格须经获准方式核验。试点可使用核验过的邀请名单，不能通过自填学校授予成员权限。

一个账户可以关联多个 Membership。其学校/组织、验证方式、状态、有效范围与核验时间独立记录。状态至少有未申请、待核验、有效、失效/已撤销。界面显示实际验证层级；控制邮箱的证明与在籍资格区分。

个人事件、任务和偏好以账户为拥有者。公开 Profile 不包含邮箱、完整课表、笔记、资料、参加历史或未公开学校信息。后台人员只按职责访问必要记录。

学校/城市情境只是页面组织选择；切换不会变更账户、删除记录或赋予权限。学校成员资格失效时，个人自建安排仍在，机构受限内容按其来源条件处理。

## 3. 页面与首次体验

- 今天：日期、下一项安排、需要处理、相关变化、常用入口、完整日程。
- 日程：日/周视图，清楚区分课程、活动、个人事项和全天事件。
- 待办：未完成、已完成、无日期、逾期；截止由用户或真实来源提供。
- 添加：选择事件或任务，填写必要字段，保存前校验。
- 导入：选择 ICS → 解析预览 → 检查问题/变更 → 确认保存 → 今天/日历查看。
- 我的：使用情境、学校资格、语言/时区、通知、数据导出与删除入口。

游客转注册时不自动上传本机文件或未确认的导入内容。保存动作说明哪些内容进入账户存储。没有记录时显示下一步入口，不能伪造演示课表。

## 4. 事件和任务的语义

CalendarEvent 保存稳定 ID、拥有者、类型、标题、开始/结束、原始时区、全天标记、来源引用、导入批次、重复规则/例外、状态、版本和本人覆盖修改。没有结束时间的来源事件不擅自补一小时；冲突判断说明信息不完整。

Task 保存标题、所属课程或目标、可选截止、日期精度、子任务、状态和来源。日期不明可先保存为无日期；只有日期的截止不能伪装成来源明确的 23:59 时间。

个人任务至少未完成/已完成，事件至少有效/已取消。过期是根据当前时间计算的展示条件，不等于被删除；用户关闭待办不修改学校记录。

产品常用时区为 Asia/Hong_Kong，用户界面可选其他时区；保存时保留源时区与时间语义。全天事件按日历日期处理，不能在转换时变到前一天。

## 5. ICS 导入规则

现有解析器只抽取基础开始时间，属性参数会丢失。需要改造或替换为能够正确解释所支持事件语义的实现；库与具体代码在实施计划选择。

首试必须识别 DTSTART、DTEND 或 DURATION、UID、SUMMARY、LOCATION、全天事件、UTC/明确时区以及课程常见的重复规则、EXDATE、RECURRENCE-ID 例外和取消。浮动时间需要用户确认使用时区。

对不支持或无法确定的规则，标明具体事件与原因，允许用户修正、跳过或取消整次导入；不得静默丢失规则后仍宣称全部成功。预览给出有效、重复、更新、有冲突和未处理的数量，最终保存结果与预览一致。

重复事件按显示区间展开，保留原规则与例外，不永久截成一节课。开始晚于结束、无效日期、重复 UID 冲突等在保存前处理。

幂等键包括拥有者、明确的来源/导入集合和源 UID。没有 UID 时使用可解释的指纹作候选去重，碰到歧义需确认，不能靠标题把不同事件直接合并。

重复导入相同文件不新增副本；同 UID 更新显示字段差异。用户对导入事件的手动覆盖保留，来源更新冲突需选择处理。文件中未出现某条旧事件不自动删除旧记录，因为导出可能只是部分范围。要完整替换某一批次时单独预览受影响记录后确认。

课程/任务/普通活动的分类在预览可改；导入来源的名字不能证明用户正式选修该课程或加入某个学校。

## 6. 今天与提醒

下一项安排根据用户时区与有效事件计算；今天包含进行中事项、当天任务及相关变更。跨日、全天、无结束时间和取消事件有明确展示，不让已取消事件继续占据下一项安排。

用户可选择提醒提前量。提醒计划与实际送达分开记录：待调度、已触发、已取消、失败等不能混称已送达。站内与系统通知分别标能力状态；没有操作系统授权时只显示可用通道，不承诺后台必达。

事件改期、任务完成、来源删除或本人关闭提醒时，撤销不再适用的调度。重复事件的提醒绑定具体 occurrence，避免改一节误改所有课程。静默设置适用于对应通道，重要类别的例外由用户明确选择。

后续活动报名由 U5 提供实际参与状态及事件引用，学校同步由 U1 提供有权限的源记录。U0 不猜测外部成功状态，也不直接修改其他领域的名额或报名。

## 7. 数据和模块接口边界

| 模块 | 负责 | 提供给其他单元 |
| --- | --- | --- |
| 身份/资格 | 当前账户、成员状态、公开与私有资料边界 | 服务端访问判断与实际验证层级 |
| 日程存储 | 事件、任务、版本、来源与手动覆盖 | 本人可访问的日/周安排与变更 |
| 导入 | 文件解析、预览、去重候选、确认保存 | 明确成功/更新/跳过/失败结果 |
| 今天组合 | 从有权记录生成下一项和需要处理事项 | 有来源的摘要，不复制成新的事实 |
| 提醒计划 | 事件/任务提醒、撤销与调度状态 | 通知单元可消费的事项和偏好 |

首次可在同一应用后端实现这些逻辑。个人安排必须有持久存储和服务端权限，浏览器 localStorage 只用于适当缓存或未保存的本机偏好，不能作为跨用户安全边界。

认证令牌、校方连接凭证与文件下载权限不进入公开页面和日志。检索、通知预览、导出复用访问规则；跨账户测试不能只检查首页看不到，还要验证直接详情、搜索和下载入口。

## 8. 异常与数据操作

区分加载、无安排、解析失败、部分导入、保存失败、离线缓存、身份过期和权限撤销。保存失败保留可恢复的输入，不显示成功；断网重试使用幂等规则。

用户可删除一项本人记录或整个导入批次，确认界面说明相关提醒和本人笔记的处理。导入记录与自建笔记分开，不能因删除文件批次连带丢失独立笔记。

导出只包含本人有权保留的内容。退出登录清理敏感缓存；账户最终删除说明记录、文件、关联内容及必要审计的处理，提供明确结果。正式试用前数据保留与备份删除政策需写入用户可读说明并验证，不以一句“支持删除”代替实现。

## 9. 验收与完成定义

必须覆盖：两个账户的读写/搜索/导出隔离；手动增改删与重新登录后持久化；含重复和例外的真实授权 ICS 样本；跨时区/全天/无结束时间；相同文件重导；部分导出不误删；来源更新与手动覆盖冲突；取消撤销提醒；保存失败可恢复；情境切换不改变权限。

界面可用性覆盖手机、桌面、键盘、字体放大与中英文长标题。不能依赖假连接状态、演示课程或开发者个人令牌通过验收。

U0 的退出条件：用户用真实自己的数据完成“输入 → 日程 → 修改 → 提醒状态 → 导出/删除”流程，关键时间与权限问题已解决。依赖学校接入的能力仍按 U1 清单列缺口。
