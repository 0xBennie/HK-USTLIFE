2026-10-03 用户纠正（优先于下文旧阶段安排）：学习数据的目标主流程为连接学校数据源后自动同步，ICS/手动录入仅作备用，不能作为自动课表能力的替代交付。Canvas负责获准读取的课程、作业截止和课程事件；正式上课课表需要SIS等校方正式来源。来源分工、当前缺口和追加验收见 [学校学习数据自动同步](2026-10-03-school-learning-sync.md)。当前自动连接仍未实施；原有ICS验收保留，但通过它不能称自动同步已完成。

## 1. 第一版目标

让 HKUST 学生在一个 iPhone App 内完成：管理今天的学习安排、查询可信校园交通与常用服务、发起或加入低压力的小型活动/学习组队。没有参与社交的学生也能独立使用学习生活功能。

本 Goal 的交付层级是**经过真实 iOS 运行验证的本地 MVP 开发验收版**，包含持久化后端与必要管理能力。公开运营、TestFlight 分发及 App Store 上架为下一道独立交付门槛，不能用开发验收版冒充已上线产品。公开内测所需的邮件服务、网络部署、正式组织者及运营责任另列准入清单。

长期范围以[总体设计 v1.2](2026-10-02-hkust-super-app-design.md)和[完整功能路线图](2026-10-02-bnbu-full-feature-roadmap.md)为准；本文件限定第一版执行范围，取代旧文件中范围更宽或不同的首试排序，不删除任何长期能力。范围冲突先按本文件执行并记录，不反复询问已确认的 iOS 优先等选择。

## 2. 三条必须连通的用户流程

1. 学习：登录 → 授权连接Canvas与正式课表来源 → 首次同步后自动显示课程/截止/有来源的安排 → 今天/周课表 → 查看课程任务和后续更新 → 提醒随之更新 → 重新登录后资料仍在。未获准时显示具体缺口，手动添加/ICS导入是用户自选备用路径，不能冒充同步成功。本地勾选不代表向Canvas提交作业。
2. 生活：选择路线/站点 → 看当日计划或公开预测 → 核对运行日/来源 → 收藏；查询服务 → 查看条件与正式办理入口。天气和未知数据不能被转述为校方决定。
3. 社交：发布具体活动/学习招募 → 另一用户查看条件 → 报名/候补/退出 → 组织者改期/取消 → 参与状态、消息和本人选择保存的日程正确更新。浏览者无需公开完整课表或主动私聊陌生人。

## 3. 页面与首版功能

| 编号 | 页面/功能 | 必须实现 | 本版边界 |
| --- | --- | --- | --- |
| V01 | 身份与本人账户 | 访客访问公共内容、邮箱登录流程、本人资料、学校资格状态、退出/删除、服务器鉴权 | 邮箱控制权不等于在籍；学校 SSO 未获批显示缺口 |
| V02 | 今天与学习 | 今日摘要、日/周视图、课程入口、任务增改删/完成、资料链接、私人短笔记 | 课程由本人手动/导入建立，不伪装正式选修 |
| V03 | 学校学习数据同步与备用导入 | 目标为获准连接Canvas/SIS后自动获取对应学习数据；保留ICS选择、预览、确认、去重、冲突处理作为备用 | Canvas不等于正式上课课表；自动同步未接通是核心缺口。ICS支持周期/例外、全天/时区；不支持项不得静默丢失 |
| V04 | 校园交通 | 已核验核心校巴方向、九巴/小巴相关查询、官方假期、来源/版本/失效状态 | 逐条列支持路线；不把三条测试夹具当全校完整库；无 GPS 不显示实时车位 |
| V05 | 校园目录 | 地点/服务分类、关键词搜索、详情、收藏、官方导航/办理入口、纠错 | 从已核验的高频地点和服务开始，覆盖清单明确；无依据不显示营业/空位状态 |
| V06 | 发现与校园墙 | 活动与学习招募列表/详情、具体条件筛选、发布/编辑/结束；基础文字/图文求助、回复、解决状态 | 权限范围明确；媒体若开放需有真实存储和删除，不放假上传按钮 |
| V07 | 参与与组织 | 报名/候补/确认/退出、本人参与、组织者名额和参与状态、改期/取消、活动评论 | 活动评论承担初期沟通；完整私信与复杂群聊后置 |
| V08 | 消息与提醒 | 站内报名/变更/回复通知及已读；设备许可下的个人安排本地提醒 | 远端推送列接入状态；不宣称收到 APNs；关闭或改期撤销旧本地提醒 |
| V09 | 我的与数据 | 私有收藏/参与/发布、基本偏好、连接状态、本人安排导出、账户及相关数据删除 | 无后台持续定位、无默认共享个人课表 |
| V10 | 运营与官网 | 受限网页后台维护来源/路线/地点/活动、处理纠错/举报/封禁；轻量介绍/支持/隐私和公开活动分享页 | 本地可运行；不自动发布到公网。学校私有内容不能进入公开分享预览 |

五入口固定为今天、校园、发现、消息、我的。课表/课程入口不藏在多层菜单里。未交付功能进入路线图或明确连接状态，不能占主要页面充当可点击占位功能。

## 4. UI 与技术决定

- React Native＋Expo＋TypeScript 开发 iOS 客户端，HeroUI Native 为主组件库候选；先验证依赖组合与三张关键屏，再确定版本并锁定。不得同时堆多套主 UI 库。
- 官网/后台沿用现有 Next.js 工程能力；读取其本地 AGENTS.md 与所安装版本文档后改动。现有网页不能代替原生交付。
- 手机通用组件使用统一颜色、字体、间距和状态规范；浅深色、中文/英文长文本和字体放大可用。主语言先完成简体中文和英文，繁体保留下一批完整翻译任务。
- 首页以当前安排和下一步为主；目录紧凑清楚；活动详情明确时间、人数、语言、地点、组织者、报名/退出方式。报名状态不只靠颜色表达。
- 卡片、列表、表单和底部弹层可以复用第三方库；周课表布局、权限和活动生命周期需要业务实现。Widget/Live Activities/Watch 不属于第一版必须交付内容。
- 后端提供真实持久化、迁移/种子数据、事务、逐用户鉴权和错误状态；不得只用浏览器 localStorage 或前端数组保存业务。默认单应用后端与关系数据库，本地可复现；具体适配现有代码后形成实施计划，不自动购买云服务。
- 复用来源登记、天气/交通接入经验、已有领域规则与 API 类型；既有 MCP 工具不是新产品完整 API。新增原生认证/会话、写入及缺失合同随实现更新文档。

## 5. 数据与外部依赖的清楚分界

公开交通、天气及学校公开页面使用本轮核验后仍有效的来源，保存最近读取时间、来源有效期与失败状态。页面时刻解析产生候选，由维护流程核对后发布，不在首次抓取变化时自动承诺新班次。

开发模式允许明确标记的测试账户、测试邮箱收件箱、演示组织者/活动及媒体，仅供本地验收；与真实内容隔离，默认不得进入公开环境。验证过程使用真实后端读写，演示内容不能成为真实供给/用户增长证据。

邮箱发送器可替换为正式供应商；没有正式配置时，只验收本地开发邮件适配器及验证码生命周期，显著标为开发登录。开发适配器只在显式本地开发环境启用；对公网配置必须拒绝启用，不返回验证码给正常认证响应。不把此状态写成可公开注册。

School OIDC、Canvas/SIS、私人 Graph 邮件、校巴 GPS、设施写入等未获批项保留缺口及替代路径。用户本次授权产品开发，不授权发送真实邮件、提交学校作业、访问私人账号、购买服务或部署。

## 6. 必须通过的验收

| 编号 | 可核验结果 |
| --- | --- |
| MV01 | 一条已记录的命令序列可启动后端与 iOS 开发环境；实际在模拟器或获准真机打开主流程，有版本/环境记录与截图 |
| MV02 | 两个普通账户和受限管理员账户完成各自流程；普通用户直接请求另一个用户的日程/笔记/导出或后台资源被拒绝 |
| MV03 | 日程/任务/收藏/报名重启后仍存在；删除、退出、会话过期与跨账号缓存隔离正确 |
| MV04 | ICS 周期课、单次取消/改期、全天、时区、重导、无结束时间及不支持规则有正确预览和保存结果 |
| MV05 | 校巴工作日/假日/末班后/学期外/数据过期分别正确；公开 ETA 断开后不继续假实时倒数 |
| MV06 | 最后一个名额的并发/重复请求不超额；候补、退出、改期/取消与本人日程/消息一致 |
| MV07 | 发帖/招募、回复、解决/结束、举报、屏蔽和管理员处理实际写入并影响对应可见范围 |
| MV08 | 编辑日程或取消活动后旧本地提醒取消；拒绝通知权限不影响基本功能；消息已读状态可持续保存 |
| MV09 | 加载、空内容、失败重试、断网和旧缓存有明确呈现；关键表单受键盘/安全区/字体放大影响仍可操作 |
| MV10 | 账户/内容删除、导出、公开分享和媒体访问符合权限；模拟数据与开发认证不可能被误发布为真实生产内容 |
| MV11 | 现有仍相关测试通过，新增 API/领域/关键移动流程测试通过；保留失败、阻塞和证据，不用参考规则测试代替服务器或手机验收 |
| MV12 | 交付启动说明、实际 API 文档、截图/测试报告、覆盖清单、已知问题及公开内测尚需条件，无死按钮或伪造成功状态 |

本地开发验收通过可以完成本 Goal，但公开运营未就绪必须明确说明。**iOS 运行验收未完成时不能宣布本 Goal 已达成**，即使网页、单元测试和打包检查通过。

## 7. 执行单元与交接

依次完成：E1 原生壳/设计基础/后端账户；E2 个人安排与 ICS；E3 交通/校园目录；E4 招募/活动/基础校园墙；E5 消息/治理/官网；E6 联调与 iOS 验收。每单元编写对应可执行计划、实现与必要测试，不再重做全量产品研究，不创建用户新聊天或启用子代理。

执行前读取仓库状态和模块指令，保留无关改动。新建/修改目录以检查结果为准，建议原生端位于 apps/mobile，业务后端与共享合同分别保持模块边界，不把全部状态和界面堆进一个文件。

当前环境只读检查：活动开发路径为 /Library/Developer/CommandLineTools，xcodebuild 未能运行，/Applications/Xcode.app 不存在。这只证明当前默认工具链不足，不排除其他位置安装。后续先检查可用 Xcode/SDK/模拟器或获准真机；需要用户安装/配置时只提出具体依赖，继续不依赖它的后端/数据工作，不宣称手机已通过。

每单元更新 docs/progress/ios-mvp-v1-handoff.md（执行时创建）：目标、已确认决定、改动路径、完成/未完成、测试证据、阻塞、下一步。模型与速度尊重当前用户设置；不自行升级、不设置 token 硬上限。
