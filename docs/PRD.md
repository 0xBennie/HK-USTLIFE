## 1. 产品目标与选择理由

### 1.1 产品承诺

让学生在一个 App 中掌握学习安排、处理校园事务，并在有需要时找到合适的人一起完成事情。基础功能独立有用；社交参与、公开表达和关系建立均由本人选择。

希望学生形成的使用理由是：重要事情找得到、变化看得懂、下一步办得清；需要伙伴时，能了解彼此的合作方式，并自然地安排下一次。

### 1.2 要解决的具体问题

| 学生处境 | 产品应产生的结果 | 观察方式 |
| --- | --- | --- |
| 学校系统、网页和群聊中信息分散 | 自动汇总获准信息，保留来源和下一步 | 完成真实事项的总耗时，包含首次授权、录入、纠错和维护 |
| 课表、DDL、个人任务与活动冲突 | 同一私人安排中看清优先事项与变化 | 冲突识别、改期与旧提醒撤销，遗漏不能增加 |
| 有项目但没有合适伙伴 | 组队前对齐时间、角色、语言和投入 | 双方确认及第一次有效协作，未成组者也计入 |
| 有任务却迟迟没开始 | 从具体任务进入有限时段的共同专注 | 实际开始/结束与自愿再次使用，拒绝公开效率排名 |
| 想参加但担心一个人、不熟悉流程 | 看清预期，允许尝试一次，选择是否继续 | 到场、体验是否符合说明、完整周期内的复参与 |
| 办事、选课和找机会怕漏条件 | 材料、规则、期限、变化与状态可核对 | 少反复找原文，个人状态不冒充学校确认 |
| 组织者反复问时间、催确认和通知变更 | 同一处协调名额、出席意愿、变更与下一场 | 实际举办、复办和每次人工协调时间 |

### 1.3 人群与长期范围

服务本科生、授课型硕士、研究型研究生和交换生，区分学制、教学阶段、语言、住宿与通勤情境。第一批价值验证优先选择近期有学习项目/复习需求的人、进入新环境的人，以及能持续组织小型活动的人。选择人群不等于对所有学生需求强度下结论。

长期支持校内、跨校和全港场景。学校切换是内容情境选择，不授予学校成员权限；活动报名不授予校园通行权。毕业后可保留平台账户与本人自建内容，原机构资格和来源权限按真实生命周期调整。

### 1.4 差异化与竞争约束

HKUST Student、USThing 已有学习与校园功能；活动管理、可用时间和共同专注也分别有现有产品。参考依据见 [USThing](https://www.usthing.xyz/)、[HKUST Student](https://studentapp.hkust.edu.hk/functions)、[Howbout](https://howbout.app/about)、[Focusmate](https://support.focusmate.com/en/articles/9110188-getting-started)。这些公开说明证明能力存在，不证明本产品的需求和留存已成立。

本产品拟验证的增量是：课程/事项提供上下文，个人时间与校园地点减少协调，明确合作预期帮助第一次协作，有限系列和双方意愿帮助下一次。数据更旧、维护更麻烦、没有真实参与者时，这个组合就没有胜出。允许保留原资料链接、正式学校办理和既有聊天工具，迁移成本也纳入比较。

## 2. 已确认的产品原则

1. iOS/iPhone 优先，React Native＋Expo 为现有工程方向；Android 暂不开发。苹果风格、浅深色和完整交互是要求。
2. 保留今天、校园、发现、消息、我的五个主入口。学校课程、交通和生活服务不因强调社交而删减。
3. 学习主流程为 HKUST 官方账号登录后，在校方批准与本人同意下自动同步 SIS/Canvas。ICS 和手动录入保留为备用。
4. 平台不收取学校密码、学校 Cookie 或共享私人令牌。学校身份登录、在籍资格、SIS 数据许可、Canvas 许可分别记录。
5. 私人课表、成绩、邮件、笔记和未公开意向默认私有。参与社交不要求交出整张课表或通讯录。
6. 信息要有来源、适用范围和时效；未知、未连接、无数据、过期和失败使用不同状态。
7. 兴趣、关注、加入圈子、报名、候补、出席、再次联系分别由明确动作产生，不互相推定。
8. 功能完成依据实际写入、跨页一致、异常恢复和对应平台验收。Pen、浏览器 mock、原生代码、真实 iOS 和学校接入分别报告。

## 3. 阶段与范围

阶段表达交付次序，不是功能重要性；外部批准可能独立影响时间。全部列入本产品规划，具体日期在人员、供给与权限明确后估算。

| 阶段 | 交付重点 | 必须达到的结果 |
| --- | --- | --- |
| R1 基础 iOS MVP | 学校登录与获准的 SIS/Canvas 自动读取、今天/学习、备用 ICS、核验交通与目录、基础活动/招募/校园墙、消息/提醒/个人数据、必要官网与后台 | 三条基础流程在真实 iOS 与持久化后端完成；学校同步独立通过。外部授权未到位可继续开发其他部分，但 R1 整体不能被标为完成 |
| R1.1 价值验证版本 | 合作预期与首次沟通、共同专注、固定小组与单次尝试、再次同行、有限的重要事务清单；条件筛选、意向和私密邀请深化 | 有真实供给的小范围使用；验证有效协作、实际复参与和事务处理收益。新增机制先做完整的小场景 |
| R2 学校与 iPhone 深化 | 课程文件/标注/打包、获准作业提交、成绩、邮件、深度地图/设施/办事、课程组合评估、帮助/住房/借用/职业专题、通知与 Widget/Live Activities、同账号多 iPhone 同步 | 对每种读写和专题分别完成权限、生命周期、运营与原生验收；不将一项授权扩大到所有数据 |
| R3 多校与苹果多端 | 香港其他学校、跨校/全港供给；iPad/Mac/Watch 两条可独立推进的工作流 | 每校资料和资格规则可维护；真实跨校参与成立；各设备单独适配和验证 |
| R4 长期能力 | 深度 AI、可控记忆/动作、Wallet 信息卡、独立评估的平台内支付；Android/Windows 保留且暂缓 | 基础业务稳定，处理方式与成本明确；其他平台需另行启动决定 |

R1.1 和后续功能会出现在设计与规划中，但未开放能力不占主要操作入口充当假按钮。开发展示可以查看未来页面，发行版本依据已验收能力开放。BNBU 对照项的具体阶段见附录。

**交付层级**：设计可审阅 → 本地后端与原生实现 → 真实 iOS 开发验收 → 学校授权及核心同步验收 → 受控学生试用 → 公开分发/运营。工程与学校接入可并行准备；R1 整体验收同时需要真实 iOS 和核心同步。公开 TestFlight/App Store 分发、生产部署和收费是独立发布动作。

## 4. 信息架构与关键流程

### 4.1 五个主入口

| 入口 | 首屏回答的问题 | 内容与后续动作 |
| --- | --- | --- |
| 今天 | 我今天要做什么，有什么变化？ | 下一节课、期限与任务、关键变化、确认过的安排；进入周课表、课程、任务、导航或本人选择的共同专注 |
| 校园 | 这件事去哪找、怎么办？ | 交通、地图、餐饮、设施、住宿/洗衣/打印/报修、部门教师、办事清单、学校机会与支持；搜索优先于无限分类 |
| 发现 | 有什么我能参加，或者谁能一起做？ | 活动、学习招募、圈子、校园墙；按时间/语言/地区/预算/资格筛选，发起需求或保存意向 |
| 消息 | 哪件事需要我注意或决定？ | 报名/候补、改期/取消、回复与联系请求；进入原对象处理。学校邮件使用独立入口和独立授权 |
| 我的 | 我的资料、关系、安排和授权由谁控制？ | 本人参与/发布/收藏、连接、偏好、身份与学业入口、设备、导出/删除、反馈支持 |

跨入口复用同一课程、地点、活动、参与记录和版本。私人源数据只有在本人主动选择后，才以明确字段进入招募或共享安排。成绩和邮件正文不默认出现在今天、锁屏或推荐理由中。

### 4.2 J01 学校登录与自动学习安排（R1）

访客浏览公共内容 → 选择 HKUST 官方登录 → 系统认证浏览器完成学校登录/MFA → 返回平台账户 → 按批准方式确认 SIS 读取与 Canvas 连接 → 首次同步 → 今天/周课表出现有来源的安排 → 查看作业/资料 → 接收后续变化 → 编辑本人任务或笔记 → 提醒更新 → 退出重登后隔离与持久化正确。

SIS 提供获准的正式课表/选课相关字段；考试等数据不在授权范围内时另列覆盖。Canvas 提供获准课程、作业与课程事件，不能单凭空日历推断没有课。正式选课、关注课程和手动创建课程分别呈现。部分同步失败保留旧数据及时间，不把部分结果当全量删除。

### 4.3 J02 交通、地点与校园办理（R1）

选择路线/方向/站点或搜索服务 → 查看适用日期、计划/预测与来源 → 导航至核验上落点或进入官方办理 → 收藏/纠错 → 在我的找回。假日、末班后、学期外、来源过期、网络失败分别显示。

地图入口不等于可用室内导航；点击设施预约、请假或报修入口不生成办理成功。天气警告不自动成为学校停课/停运决定。本人收藏不授予乘车、入场或预约资格。

### 4.4 J03 活动与基础招募（R1）

发起人写明事情、时间、地点、人数、语言、费用/资格和接应方式 → 保存草稿 → 预览 → 发布 → 另一用户查看 → 报名/申请/候补 → 获得明确状态 → 自选加入个人日程 → 发起人改期/取消 → 消息、参与、日程及提醒一致 → 自愿反馈或退出。

同行小组与第三方正式活动报名分开；每场活动记录唯一的名额主系统。外部状态未同步时保持未知。报名写入后读取刷新失败，应提示已保存但刷新失败；写入结果未知时查询或使用同一请求标识重试。

### 4.5 J04 合作预期与第一次协作（R1.1）

课程/任务 → 选择允许自主组队或已有队伍 → 填角色、语言、预计投入、可协商时段与节奏 → 预览主动共享内容 → 接收申请 → 可选一次短沟通 → 双方确认合作 → 明确第一项分工/第一次会面 → 任务、资料与后续安排继续关联。

短沟通的默认 15 分钟是可调整设计参数。邀请沟通不等于加入队伍；未知课程规则先核对。成员退出或任务结束后停止相应访问，历史本人贡献与他人私密内容分开处理。不要设置公开人格或“靠谱程度”评分。

### 4.6 J05 共同专注与稳定小组（R1.1）

从本人任务选择共同专注，或从发现选择一个已安排的小组 → 查看地点、语言、交流预期、时长、主持和费用 → 只参加一次或明确选择系列 → 到场/开始 → 自愿记录完成情况 → 私下表达是否愿意再见 → 双方同意时建立联系 → 独立确认下一次出席。

25/50 分钟专注、3–5 人小组、连续四周均为试点参数，可调整，不是效果承诺。可安静参与，不强制开摄像头、分享屏幕或公开完成量。一次报名不自动加入永久群；系列调整只影响指定场次。没有供给时可保存可撤回的意向，不生成假参与者。

### 4.7 J06 重要事务与机会（R1 清单；R1.1 变化与进度；R2 深化）

选择与本人阶段相关的事务 → 查看适用条件、材料、步骤、官方来源和截止 → 保存私人进度 → 标记本人准备/外部已提交 → 有可信回执时记录官方状态 → 来源变化时展示原值/新值及影响 → 用户确认如何调整。

覆盖新生、住宿、交换、奖学金、比赛、职业与研究机会等已维护场景。本人勾选、本人报告已提交、官方收到/批准必须分开；不能根据学校/年级推断具备全部资格。外部无法验证的状态允许本人记录并标明来源。

## 6. 状态、权限与跨模块规则

### 6.1 学校连接与登录

连接至少支持：待学校批准、未连接、同步中、已连接、部分覆盖、需要重新授权、已撤销、错误。记录最近尝试和最近成功时间，不以本次请求时间伪装最新源数据。

学校官方登录使用获批方式及系统认证浏览器，验证回调、身份与发起端绑定。学生同意不替代 ITSO 应用注册或 SIS 数据拥有者批准；不能预设学校一定提供逐用户 SIS OAuth 页面。平台也不要求用户另建密码作为学校主流程的额外必经步骤。

若学校连接不可用，公共信息可继续看；用户可选择手动/ICS 的备用安排。未连接页说明具体缺口和可用操作，不能显示已连接或“今天没课”。撤销后停止新读取，并阻止在途任务写回；上游撤销结果与平台撤销分别展示。

### 6.2 学习与来源状态

来源事实与个人层分开：正式日期/班别/状态不被私人别名、笔记或完成勾选覆盖。跨来源课程用可信标识映射，名称相似不自动合并。完整抓取与部分分页结果分开，源端缺失一项不能未经语义确认就删除。

私人安排可处于草稿、保存中、已保存、待确认、完成/取消；学校作业可另有已发布/提交/评分等获准状态。界面明确说明记录来源。重复、时区、全天、无明确结束时间及单次例外贯穿日/周视图、搜索、提醒、Widget 和导出。

### 6.3 活动、关系与意向

| 对象 | 需要区分的状态 | 关键规则 |
| --- | --- | --- |
| 活动 | 草稿、发布、满员、改期、取消、结束 | 写入回执和读取刷新分开；一次修改明确作用于场次还是系列 |
| 参与 | 申请中、已确认、候补、待再次确认、退出、拒绝/过期 | 候补不是报名确认；兴趣不是申请；重大条件变化允许重新选择 |
| 出席 | 本人/组织者提供的确认、未知、未到场 | 报名不自动算出席，未知不自动算爽约 |
| 合作 | 沟通邀请、沟通中、双方确认、进行中、结束/退出 | 接受沟通不自动承担整个项目；记录共同同意的分工 |
| 关系 | 单方意愿、双方同意、撤回、屏蔽 | 不公开单向意愿；建立关系也不开放私人课表 |
| 需求意向 | 私人草稿、同意协调、提出方案、到期、撤回 | 不占名额；方案落地后重新确认；停止分享即停止相应协调 |

付费、外部报名、校内准入分别核对。第三方状态未知时不允许用本地报名或 ICS 日程代替。申请、重试、取消等动作需要幂等、版本检查和跨账户鉴权。

### 6.4 内容可见性与治理

可见范围包括公开网页、平台成员、指定学校有效成员、圈子成员、活动参与者和仅本人。内容对象自己保存范围，切换筛选不改变范围。公开预览、分享、搜索索引、通知摘要与导出遵守同一规则。

校园墙以可追责的账户体系为基础；匿名/假名公开机制不默认启用。需要该模式时另行定义审核、反骚扰与身份保护。举报、屏蔽、内容删除、成员退出和资格失效必须传播至搜索、推荐、缓存和通知。

媒介文件上传需有真实鉴权、类型/大小限制、存储、访问撤销、删除和举报流程。尚未开放时不展示假上传成功。管理员只得到处理职责需要的数据，不因后台身份获得所有私人内容。

## 7. UI、交互、动效与 Pen 对应

### 7.1 视觉与平台要求

统一系统字体、清楚层级、中性色分组背景和蓝色操作强调；危险操作使用语义颜色与文字。iPhone 常规参考字号为大标题 34、正文 17、辅助 13，必须支持字体放大；点击区域至少 44pt。头像、插图、图标与地图样式一致，不照搬参考产品品牌或学校素材。

信息密集页面以可扫读的列表和分组呈现；主动作明确，次要动作放在合理的详情或菜单。课程和活动详情优先显示学生要判断的条件。地图、交通和状态不只靠颜色。公共网页展示真实产品价值与已交付状态，未来能力明确标注。

### 7.2 全局交互与恢复

每个主流程覆盖加载、空态、失败、旧数据、权限不足、保存中、结果未知和成功。列表进入详情后返回恢复上下文；Tab 切换保持合理状态；编辑未保存时提供继续编辑、保留草稿和放弃，明确草稿是否仅在当前会话中保留。

提交时防重复点击，结果未知保留原请求与输入，不能通过换一个请求标识制造重复操作。账号退出/删除、导航和异步完成必须考虑草稿与晚到回调。成功反馈绑定真实回执；手机键盘、安全区、长文案、字体放大、VoiceOver 和实际触摸均需要验证。

### 7.3 动效规则

| 场景 | 目标体验 | 验收要求 |
| --- | --- | --- |
| Tab/详情/返回 | 方向与层级清楚，过渡短且不抢内容 | 不因重挂载丢输入，返回恢复位置；跟随平台手势 |
| 弹层/确认 | 用户知道作用对象和取消方式 | 焦点、背景可操作范围、键盘避让正确 |
| 保存/报名/候补 | 操作后立即有反馈，最终状态可辨 | 网络慢/失败/未知不播放虚假完成动效 |
| 触觉 | 仅对合适确认和操作使用轻量反馈 | 在真实 iOS 设备验证，关闭或不支持时流程仍完整 |
| 减少动态/透明度 | 保留信息与操作，减少位移/模糊 | 响应系统设置，无必须依赖动画的内容 |

现有浏览器展示的 140–220ms 等时长是演示实现记录，不是原生动画已验收的证明。最终以原生交互和系统可访问性检查为准，不用 CSS 透明效果宣称实现原生 Liquid Glass。

当前 [Pen 索引](../design/presentation/README.md)列出 102 个可编辑 iPhone 页面/状态、8 个深色样例和 7 个组件。页面数量包含失败/空态/确认，也包含后续概念。英文和大字号仅有代表页，官网/后台不在这 102 页中。

### 8.2 领域对象与最小字段

身份对象分为 User、Membership、Connection 和 Consent；不将学校资格混入可由客户端编辑的普通资料。课程/任务保留 owner、source、external ID、版本、日期精度、时区、适用期与私人覆盖。地点和交通保留校区、来源版本及核验期限。

活动/招募保留可见范围、资格、语言、时间、地点、名额主系统与版本；Participation 与 Attendance 分开。合作预期、系列场次、再次同行意愿、办事模板/本人进度分别建模，避免混在一个“已加入/已完成”布尔值里。内容与媒体记录生命周期，通知只引用有权限的目标。

### 8.4 技术基线

现有本地后端不等于手机可访问的测试服务。真机需获准的安全网络配置，签名/安装需实际账号和设备路径。EAS 云构建与本机 Xcode 是运行方案选择，编译、原生导出、安装和交互验收分别记录。

## 9. 留存、增长与运营

### 9.1 持续使用的理由

学习用户回来处理下一项任务与变化；合作用户回来推进共同任务；参与者回来见熟悉的人或参加下一场；组织者回来减少重复协调。允许学生只使用其中一部分。转去既有聊天工具不必视为失败，产品应凭安排和后续机会继续提供价值。

增长依次验证：具体任务邀请伙伴、真实组织者分享公开活动、经同意的需求促成供给、经过授权且仍有效的经验帮助下一批学生。私人内容不默认用于公开获客，不以邀请人数解锁学习工具。

先集中在有限课程、时段和可到达地区。扩展到新学校前确认资料维护、资格、参与条件、主持/场地与持续供给，不能用假活动填充全港页面。

### 9.2 指标与证据

| 人群/目标 | 激活与复用口径 | 同时记录 |
| --- | --- | --- |
| 学习/事务 | 保存或同步真实事项，在另一次使用中找回/处理；第 2/4 周继续处理 | 完整激活分母、教学周/假期、设置/维护耗时、错误和漏项 |
| 学习合作 | 双方确认后发生第一次有效协作；两周后继续合作或完成原目标 | 未成组/退出者、首次协作耗时、预期是否一致、人工支持 |
| 小组参与 | 首次实际到场；28 天内再次实际参与 | 确认依据、未知出席、取消、无后续供给也保留在分母 |
| 组织者 | 首次实际举办；完整四周内复办 | 原计划频率、协调分钟数、取消、主持与平台支持成本 |
| 质量 | 关键状态与来源正确，错误有恢复 | 投诉/申诉、越权、提醒错误、资料过期、不可用功能 |

建议沿用先访谈真实近期事项、再有限两周试用、随后完整 4–6 周观察的路径。人数和目标阈值是实验设计，不写成已测到的行业水平。观察期未满者单列；没回复不算满意，报名不算到场。

若组队仍靠创始人大量撮合、系列无人复来、来源维护比现有办法更费时，应缩小场景或调整机制，不能靠推送、签到压力和补造内容解释留存。基本学习生活与社交优先免费，组织者工具/服务费等商业模式另做真实付费验证。

## 12. 推进顺序与责任

本次交付是完整 PRD。后续按单元读取本文件及专项规格，先补核心依赖和设计/代码差异，再执行开发计划。

1. 统一学校登录与同步合同、能力状态和原生运行路径；取得校方确认前继续独立工程准备。
2. 完成 J01–J03 的真实数据与 iOS 验收，检查 Pen 与原生的跨页状态和恢复。
3. 围绕有限真实课程/组织资源设计并实施 X01–X05；先验证合作和复参与，再扩大匹配范围。
4. 按数据许可、运营能力和真实使用结果，推进 R2 学校深度能力及 X06–X11 专题。
5. 按每校来源、资格与供给准备情况扩展全港；苹果多端可独立推进。Android/Windows 继续暂缓。

工程负责人维护需求→设计→API→运行证据；来源维护负责人复核关键时刻/规则；组织负责人确认主持与场地；治理负责人处理举报与申诉。发布前由项目负责人落实这些角色及实际服务能力，不用文档角色代替有人负责。

目前不具备确定发布日期和总预算的依据。主要外部决策是学校申请主体与数据许可、获准 iOS 账号/设备/签名/测试网络、真实组织者与试用范围，以及媒体/住房/借用/支付等专题开放时的维护能力。它们需要在对应交付前解决，不通过删除需求或伪造连接绕过。
