## 1. 理念与原则

**一句话**：Campus 不等学生来找信息——它在对的时间把**下一步该做的事**推到锁屏，学生点一下就做完；同一份数据也开放给学生自己的 AI。

### 三条原则

1. **主动但克制**
   - 每条推送都必须回答「现在不看会有什么损失」。答不出来的，进今天页卡片，不进锁屏。
   - 全局预算：除时间敏感类（出门、截止 3h、停课）外，**每天锁屏推送 ≤ 6 条**；超出合并进 22:00 晚间预告或次日早报。
   - 上课中、考试中、睡眠时段（默认 00:30–07:30）、系统专注模式下一律静默，结束后合并一条摘要。
   - 同一对象 24 小时内不重复推送同一种提醒；学生连续 3 次划掉同类推送，自动降级为「只进卡片」并告知。

2. **每条推送可以直接操作**
   - 每条通知至少一个有意义的按钮（完成、稍后、导航、加入日历、续借、接受候补），按钮在锁屏直接执行，不必打开 App。
   - 点通知本体必须**深链接到具体对象**（那份作业、那班车、那个活动），不是落到首页。
   - 动作有回执：执行成功替换为「已完成 ✓」（更新通知或下一次打开显示 Toast），失败给可重试入口。

3. **学生掌控数据**
   - 学校密码和 Cookie 永远只在本机（沿用 V2 修订）；服务器只收解析后的结构化记录。
   - 每一类推送可单独开关，并显示「依据什么数据、多久更新一次、上次成功时间」。
   - 锁屏默认**隐私遮罩**：成绩、邮件主题、私人日程在锁屏显示「有 1 项成绩更新」，解锁后才显示具体内容。
   - 学生 API 钥匙由学生自己创建、限定范围、随时吊销；每次调用有日志可查。

## 2. 主动卡片 / 推送目录

### 2.1 统一模型

每个触发器产出一个 `ProactiveItem`，同时决定它出现在哪里：

```
ProactiveItem {
  id, kind (下表编号), owner,
  surface: 'push' | 'card' | 'live_activity' | 'widget',   // 可多选
  priority: 'time_sensitive' | 'active' | 'passive',          // 对应 iOS interruptionLevel
  fires_at, expires_at,                                        // 过期自动撤下卡片/通知
  title, body, body_locked,                                    // body_locked = 锁屏遮罩文案
  category,                                                    // iOS 通知类别 → 按钮组
  deep_link: 'campus://deadline/123',
  source: { kind: 'canvas'|'sis'|'shuttle'|'kmb'|..., fetched_at },
  dedupe_key                                                   // 去重与合并
}
```

- `priority` 映射：`time_sensitive` 可穿透专注模式（需 entitlement，学生可在系统设置关闭）；`active` 普通；`passive` 不响不亮，只进通知中心。
- 来源字段直接对应 PRD 原则 6（来源、时效可见）。

| F4 | 数据失效提醒 | 学校会话过期且有依赖它的提醒已计划 | 会话状态 | **学校连接已过期** · 截止和成绩提醒暂停了，重新验证 30 秒 | 「重新连接」 | 我的 → 连接中心 | 每 24h 1 次 | 这是唯一可解释「为什么没提醒」的通知，不得省略 |

共 **6 + 7 + 7 + 7 + 4 + 4 = 35** 项。P0 只做加粗的 10 余项（见 §6）。

### 2.3 文案规范

- 标题 ≤ 18 个汉字，先说**结果/动作**（「10 分钟后出门」），再说对象；正文 ≤ 2 行，给出一个具体数字（时间、地点、名次）。
- 不用感叹号、不用 emoji、不用「亲」。中英按 App 语言，课程代码保持英文。
- 锁屏遮罩版（`body_locked`）：成绩、邮件、私人日程、健康类。
- 合并文案：「另有 3 条已合并到晚间预告」——让学生知道克制是有意为之。

### 2.4 预算与调度（本地通知 64 条上限）

- 当前 `ReminderController` 已占 60 条上限。改为**分池**：时间敏感 20 条（A1/A3/B3/C2/D6/E2）、截止 20 条、节奏 10 条（未来 5 天早晚报）、其它 10 条；超出部分写入 `deferred`，下次打开或后台刷新时补排。
- 动态内容（实时 ETA）不能提前排死：A1/A4 先排一个「占位」通知，后台刷新（`BGAppRefreshTask`）在 T−20 分钟更新文案；若刷新没跑，占位文案只说「约 10 分钟后该出门了」，不报具体车次。

## 4. 学生数据 API / MCP

### 4.1 定位

「你的校园数据，你的 AI 也能用。」学生在 Campus 里创建一把**个人钥匙**，把它填进 ChatGPT、Claude、快捷指令或自己的脚本，AI 就能回答「我这周最忙是哪天」「帮我排一个复习计划」「下一班去坑口的车」。

和 PRD 原则 4 的关系：我们**不收**学校密码和 Cookie；这里是**我们发给学生**的钥匙，只能读学生已同步给 Campus 的结构化数据，可随时吊销——方向相反，不冲突。需在 PRD §2 补一句说明。

### 4.2 个人 API 钥匙

| 项 | 设计 |
|---|---|
| 格式 | `cmp_live_` + 32 字节随机；服务器只存 SHA-256 哈希；创建时只显示一次（可复制、可生成二维码给电脑扫描） |
| 数量 | 每人最多 5 把，每把有名字（「Claude 桌面」「快捷指令」） |
| 有效期 | 默认 90 天，可选 7/30/90/永不（「永不」需二次确认）；到期前 7 天通过 F 类通知提醒 |
| 范围（scope） | 创建时勾选，默认只勾公开类 + `today:read` |
| 吊销 | 一键吊销单把；「吊销全部」；退出登录、删除账号、学校连接断开 → 依赖学校数据的 scope 自动失效 |
| 速率 | 每把 60 次/分钟、5000 次/天；超出 429 |
| 审计 | 每次调用记录：时间、钥匙、端点/工具名、返回条数（不记录内容）；学生在「API 使用记录」可看最近 30 天 |
| 写操作 | P0/P1 **只读**。P2 才开放 `deadlines:write`（标记完成）、`reminders:write`，且每次写入在 App 内生成一条站内消息回执 |
| OAuth | P2：为 ChatGPT/Claude 连接器提供标准 OAuth 2.1（PKCE + 动态客户端注册，MCP 授权规范要求），学生在 Campus 授权页勾 scope，免复制钥匙 |

**Scope 列表**

| scope | 内容 | 敏感度 |
|---|---|---|
| `public:read` | 校巴、KMB/GMB、地点、天气、公开活动 | 低（无钥匙也可匿名限速使用） |
| `today:read` | 今日聚合（课、截止、下一班、活动） | 中 |
| `schedule:read` | 课表、考试时间 | 中 |
| `deadlines:read` | Canvas 作业/截止、提交状态 | 中 |
| `announcements:read` | Canvas 公告正文 | 中 |
| `activities:read` | 我报名/候补的活动 | 中 |
| `affairs:read` | 重要事务清单 | 中 |
| `grades:read` | 成绩、GPA | **高**：默认不勾；勾选时红色说明「AI 服务商会看到你的成绩」；单独有效期上限 30 天 |
| `mail:read` | （spike 成功后）邮件主题与 AI 提取的截止 | **高**：同上 |
| `deadlines:write` / `reminders:write` | P2 | 中 |

> 成绩、邮件：由于服务器默认不保存成绩明细（只在本机），`grades:read` 需要学生在设置里打开「把成绩同步到 Campus 服务器以便 API 使用」——明确的第二道开关。

### 4.4 MCP 服务器升级（基于现有 `hkust-life-mcp`）

现状问题：`src/http.ts` 用单一 `HKUST_MCP_API_KEY` 校验，没有学生身份；工具大多接受调用方传入的数据（如 ICS 文本），读不到 Campus 里该学生的数据；`hkust_get_outlook_signals` 依赖环境变量 Graph token，不适合多用户。

升级方案：

1. **托管 HTTP MCP**：`https://api.<域名>/mcp`，Streamable HTTP（已用 `StreamableHTTPServerTransport`）。认证改为个人钥匙（P1）→ OAuth 2.1（P2），按钥匙解析 `owner` 与 scope，**工具列表按 scope 动态返回**（没有 `grades:read` 就看不到成绩工具）。
2. **保留本地 stdio 版**（`src/index.ts`）给进阶学生，配置 `CAMPUS_API_KEY` 环境变量即可。
3. 工具集（命名沿用 `hkust_` 前缀；现有工具保留，新增个人工具）：

| 工具 | scope | 说明 |
|---|---|---|
| `hkust_get_today`（替代 `hkust_build_today` 的个人版） | today:read | 读 `/me/today` |
| `hkust_get_next_class` | schedule:read | 「我下节课在哪」 |
| `hkust_list_deadlines` | deadlines:read | 参数 `within`、`course` |
| `hkust_get_schedule` | schedule:read | 时间范围 |
| `hkust_list_exams` | schedule:read | — |
| `hkust_next_departure` | public:read | 起终点 |
| `hkust_get_daily_brief`（现有，改为读本人数据） | today:read | — |
| `hkust_get_grades` | grades:read | 高敏 |
| `hkust_plan_study_week` | deadlines:read + schedule:read | 返回空闲时段 + 截止，供 AI 排计划（只计算不写入） |
| `hkust_add_reminder`（P2） | reminders:write | 写入需用户在 AI 端确认；Campus 内回执 |

4. **MCP Resources / Prompts**：把「教你用 AI」的提示词模板以 MCP `prompts` 形式提供（如 `weekly_plan`、`exam_revision`），在 Claude/ChatGPT 里一键调用。

### 4.5 隐私与吊销

- 数据最小化：API 不返回学号、邮箱、同学信息；活动参与者只返回人数。
- 第三方 AI 的数据去向在创建钥匙页明确写：「你把钥匙给谁，谁就能按你勾的范围读数据；ChatGPT/Claude 是否保存对话，由它们的政策决定。」附官方设置链接。
- 异常检测：同一钥匙 1 小时内来自 > 3 个国家/地区 IP，或调用量突增 10 倍 → 自动暂停并推送「你的钥匙被暂停」（带「恢复」「吊销」按钮）。
- 钥匙泄露自助：钥匙格式固定前缀，可登记 GitHub secret scanning 合作伙伴（P2），泄露自动吊销。
- 删除账号：所有钥匙、审计日志 30 天内删除，与 `/me` DELETE 现有流程合并。

### 4.6 学习板块「教你用 AI 管理生活」

## 6. 分阶段路线

### P0（两周）：让第一批推送「有用且能直接操作」

| 交付 | 说明 | 验收 |
|---|---|---|
| `ProactiveItem` 模型与设备端规则引擎 | 扩展 `reminders/projection.ts` 与 `ReminderController`：分池预算、去重、合并、静默时段 | 单测覆盖预算、合并、静默；64 条上限下不丢时间敏感项 |
| 通知类别与按钮 | 6 个 category：截止（完成/稍后）、出行（倒计时/换一班）、活动（参加/退出）、学校（查看）、节奏（看今天）、连接（重新连接） | 模拟器与真机锁屏点按钮，状态写回并在 App 内一致 |
| 首批触发器 | **B2、B3、B1、A1（时刻表版，无实时更新）、F1、F2、E1（App 打开/后台刷新时拉取）、F4、D1（手动开始计时）** | 每项在真机收到一次，按钮可用，深链接落到具体对象 |
| 时间敏感 entitlement、`expo-background-task` | 一次重建 dev client | 后台刷新实际触发的日志证据（真机） |
| 今天页主动卡片堆叠 + 我的 → 自动化设置页 | Pen 画板先行，再原生 | 跨页一致：卡片完成 ↔ 通知撤下 ↔ 通知中心记录 |
| 文案与遮罩 | 全部 P0 文案中英双语；锁屏遮罩 | 文案评审清单 |

> P0 不做：APNs、Live Activity、Widget、API 钥匙。原因：都需要原生 extension 或服务端新基础设施，两周内做不到可验收。

### P1（约 4–6 周）

- APNs 远程推送（活动改期/候补转正/回复实时到达）；静默推送唤醒同步。
- C1 成绩、C2 候补递补、C4 考试公布、A3 课室改动、B6 公告（依赖设备后台同步可靠性）。
- A1 升级为实时 ETA；A4/A5/A6、D6 天气停课。
- **Live Activity**：截止倒计时、下一班车（本地启动，本地更新）。
- **Widget**：今日截止（中）、下一节课（小）、锁屏下一班。
- **App Intents**：3 个只读意图（下节课在哪、今天截止、下一班车）+ Siri 短语。
- 消息页通知中心。
- **个人 API 钥匙 + 只读 REST（today/schedule/deadlines/public）+ MCP 托管 HTTP 版按钥匙鉴权**；教程卡 1–5；3 个快捷指令配方。

### P2（之后）

- OAuth 2.1 连接 ChatGPT/Claude（免复制钥匙）；写操作 scope；MCP prompts。
- 交互式 Widget、Focus Filter、Spotlight、AlarmKit。
- Live Activity 远程更新（ETA push-to-update）。
- 宿舍洗衣/设施预约/图书馆接入（D2、D3、D5），视设备会话抓取可行性。
- 邮件（spike 成功后）进入主动层与 `mail:read`。
- 学生作品展示：「同学用 API 做的工具」栏目（审核后展示）。

## 7. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| **推送疲劳 → 学生关掉通知权限** | 主动层整体失效，且 iOS 关掉后很难再打开 | 每日预算 + 合并 + 连续划掉自动降级；首周只开 P0 中 5 项；监测「通知授权保留率」「划掉率」作为核心指标 |
| **设备端同步不准时**（后台刷新由系统调度） | 「成绩出了」「候补递补」延迟数小时；出门提醒用的是旧 ETA | 文案不承诺实时（「我们刚发现…」）；对时效要求高的出行类以时刻表兜底；P1 用静默推送唤醒；在设置页显示「上次同步时间」 |
| 学校会话过期 | 依赖学校数据的提醒全部停摆，学生不知道 | F4 必发；今天页卡片底部状态条；静默续期 |
| 学校页面改版导致解析失效 | 截止/成绩错误推送（比不推送更糟） | 解析器热更新；变化类推送（课室改动、成绩）加合理性检查（一次同步改动 > 50% 记录时暂停推送、上报） |
| 学校 IT 政策（自动化访问、数据外流到第三方 AI） | 合规风险，可能被要求下线 | API 默认不含成绩/邮件；高敏 scope 两道开关；与学校沟通时强调「学生本人数据、本人授权、本人可吊销」；保留关闭 API 的总开关 |
| 学生把钥匙贴到公开地方 | 个人数据泄露 | 默认 90 天过期、只读、前缀扫描、异常 IP 自动暂停、只显示一次 |
| 第三方 AI 给出错误建议（错误日期、错误车次） | 学生误课/误交 | API 返回 `source`、`fetched_at`、`stale`；MCP 工具描述要求 AI 引用时间来源；教程中明确「以 App 为准」 |
| Expo 原生扩展复杂度（Widget/Live Activity/Intents 都是 Swift） | 开发与审核周期长；dev client 频繁重建 | 一次性加齐 extension 骨架；P1 只做只读、本地更新版本；`@bacons/apple-targets` 管理 target，避免手改 Xcode 工程 |
| iOS 64 条待发通知上限 | 提醒被挤掉 | 分池 + 后台补排；在自动化页显示「已安排 / 待补排」 |
| 时间敏感通知被滥用 → App Store 审核或用户反感 | 被拒或被关 | 只给 6 类真正时间敏感的触发器；可单独关闭 |
| 「AI 生活方式」叙事超前于数据覆盖 | 学生连上 AI 后发现数据很少，失望 | 教程从 `public:read`（交通、天气）开始，不连学校也能体验；学校数据就绪后再推进阶卡片 |
