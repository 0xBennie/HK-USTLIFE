依据：`docs/PRD.md` v2.0、功能登记表、`apps/mobile` 与 `src/product` 现有代码、Pen `design/campus-apple.pen`、iOS 模拟器实测、外部资料（文末）。

## 修订（同日）：学校数据改为参照 USThing 的设备端登录

用户决定：不让学生手动导入课表，参照竞品 USThing 的做法。依据：
- USThing 要求学生输入 ITSC 账号密码并通过 Duo 2FA，由其开源抓取器 Excalibur（无头浏览器）登录 SIS，读取课表、选课和候补状态、成绩、学籍信息；应用商店说明凭证只在本机加密保存。
- 自 2022-06-06 起，HKUST 的 CAS 已并入 Microsoft 登录（HKUST SSO Service），SIS、Canvas、Outlook 共用同一套 Entra ID 登录和 2FA。

**采用方案「学校账号设备端会话」**（比 USThing 更进一步：我们不经手密码）：
1. App 内浏览器打开学校官方 Microsoft 登录页，学生在该页输入密码并完成 Duo 或 Authenticator 验证；App 不读取、不保存密码。
2. 登录产生的会话 Cookie 只保存在本机 Keychain；同步在设备上进行：读取 SIS 课表、选课状态和成绩页面并解析；用同一会话调用 Canvas 的作业、日历和待办接口。
3. 会话过期时提示重新验证（Excalibur 记录 CAS Cookie 很快过期，需设计静默续期和失败重登）。
4. Outlook：同一会话可访问网页版 Outlook，但没有稳定的公开接口，列为**技术验证（spike）**；成功前首页的邮件段先用「分享到 Campus」。
5. 服务端只接收解析后的结构化记录（课程、截止），不接收 Cookie 或密码。

**风险（已告知，按用户决定推进）**：学校页面改版会导致解析失效，需要监控和快速修复；学校 IT 使用政策对自动化访问可能有限制；会话频繁过期影响体验。缓解：解析器做成可热更新的规则；保留手动入口仅作兜底，不作为主流程。

因此下文第 0、2、3、9 节中「需要 ITSO 批准」「Canvas 订阅链接」「R0 拆分」的判断，以本修订为准：**学校登录与自动同步重新成为第一版主流程，不再依赖学校审批。**

## 0. 一页结论（初稿，部分已被上方修订取代）

1. **首页（今天）要回答「我今天必须处理什么」**：截止日期、今天的课、需要我回应的邮件和活动变化，然后才是下一班车。现在原生首页是一张日历表单，答不出这个问题。
2. **截止日期目前没有任何真实来源。** 学校同步只有框架（`school/sync.ts` 明确写着没有网络适配器），日历只支持手动导入 ICS 文件。首页想好看，先要有数据。
3. **最快的真实来源是学生自己的 Canvas 日历订阅链接**：含作业和截止，未来 366 天，不需要学校审批。但它是私人凭证，与 PRD 原则 4「不收取共享私人令牌」冲突，需要你决定（见第 9 节）。
4. **Outlook 很可能需要学校管理员批准。** 微软 2025–26 年把第三方应用读取 Exchange 邮件改为默认需要管理员同意（MC1163922），大学租户通常也关闭学生自助授权。它和 SIS 一样是外部依赖，要尽早向 ITSO 申请。在批准前，用「从 Outlook 分享到 Campus」做零授权的替代方案。
5. **R1 完成条件锁死在学校审批上**，团队无法控制。建议拆出可试用的 **R0「学生日常版」**：Canvas 订阅、手动和分享添加、校巴和实时小巴、活动。学校 SSO、SIS 和 Outlook 作为独立里程碑并行申请。
6. **UI 的根因**：Pen 有 140 张画板，原生只移植了 2 页；没有导航栈、组件层薄、文件以单行压缩代码为主。规则已改为「Pen 是唯一 UI 来源」，下一步是按批次设计并移植。

## 1. 学生的一天：首页该出现什么

| 时间 | 学生在想什么 | 首页应给出 | 数据来源（现状） |
|---|---|---|---|
| 08:30 出门前 | 今天几节课？有什么今天截止？ | 今日简报：课程、今日截止、逾期 | 课表：SIS 未接通；截止：无来源 ❌ |
| 10:20 课间 | 下节课在哪个课室？ | 下一节课卡片：课室和电梯号 | 课室：SIS 或手动 |
| 12:30 午饭 | 有人约饭吗？群里说的活动改时间了吗？ | 活动变化、消息 | 活动和消息 ✅ |
| 15:00 自习 | 这周还有什么要交？ | 本周截止列表，按紧急程度 | 截止 ❌ |
| 17:20 回家 | 下一班车几点？ | 我的下一班（校园页已设计） | 校巴时刻表 ✅、小巴实时 ✅ |
| 22:00 睡前 | 老师今天发了什么通知？明天要准备什么？ | 未读重要邮件摘要、明日预告 | 邮件：未接入 ❌ |

**首页信息顺序（V2）**：
1. 今日概览：日期、今天剩余课程数、今日截止数。
2. 「现在」：下一节课，或正在进行的课。
3. 截止日期：今天、明天、本周三段，逾期置顶标红，可直接勾选完成。
4. 需要你处理：邮件（接入后）、活动变化、报名或候补结果。
5. 今天的安排时间线：课、私人日程、活动。
6. 小组件位：我的下一班（压缩成一行，点击进入校园）。

没有数据时，每一段都有明确的连接引导（例如「连接 Canvas 截止日期」），不显示假数据，也不显示「今天没课」误导。

## 3. PRD 需要修改的地方

| 位置 | 现在写的 | 问题 | 建议改为 |
|---|---|---|---|
| §3 阶段表 R1 | 学校登录和 SIS/Canvas 自动同步是 R1 必需 | 完成条件取决于外部审批，团队无法推进到「可试用」 | 新增 **R0 学生日常版**（Canvas 订阅、分享添加、交通、活动、消息）；R1 改为「学校连接里程碑」 |
| §2 原则 4 | 不收取共享私人令牌 | 一刀切会排除 Canvas 订阅这个唯一的零审批截止来源 | 区分「学校密码和 Cookie（永不收取）」与「学生自愿提供、可撤销、只读的个人订阅链接（加密保存，可删除，说明风险）」 |
| §4.1 今天 | 「下一节课、期限与任务、关键变化」 | 没有优先级和空数据策略 | 采用本文第 1 节的六段顺序和各段空状态 |
| §4.1 / 5.7 邮件 | 邮件 R2；「邮件正文不默认出现在今天」 | 用户明确要求日常看邮件 | M01 只读提前到 **R1.x**（取决于 ITSO 批准）；今天页只显示发件人、主题和 AI 提取的截止，正文点开才读 |
| §5.7 新增 | — | 缺零授权方案 | 新增 **M05 从邮件添加**：iOS 分享扩展，生成待办或截止草稿，本人确认后保存 |
| §5.9 通知 | Widget 在 R2 | 首页价值最大的延伸就是锁屏和桌面小组件 | 「今日截止」小组件提前到 R1.1 |
| §7 UI | 字号和原则，约一页 | 没有页面级规范，导致原生乱做 | 改为引用 Pen V2 画板和 AGENTS 规则：每个页面一个画板、一个评审记录 |
| §7.3 动效 | 原则描述 | 没有数值，无法验收 | 引用本文第 6 节动效表 |
| 功能登记表 | 无实现状态列 | 无法看出做了什么 | 增加「Pen 画板 / 原生 / 后端 / 真实数据 / 验收」五列 |
| §9 指标 | 多个口径 | 缺北极星指标 | 北极星：**每周处理的截止和事项数**（完成或提前处理），辅以 D7 留存 |

## 5. 全页面设计清单（Pen V2，按批次）

每页交付：一个画板（含主要状态）、一份学生视角评审记录（9 项检查）、交互说明和动效编号（见第 6 节）。

**批次 A：每天都用（先做）**
1. 今天 V2：今日概览、截止三段、需要处理、时间线、下一班一行。状态：第一次使用、无截止、逾期、数据过期。
2. 截止详情：来源（Canvas、邮件、手动）、提醒、标记完成、找人一起做（接活动和组队）。
3. 连接中心：Canvas 订阅、Outlook（待批准）、SIS（待批准），各自状态和撤销。
4. 添加（Sheet）：任务、截止、日程；系统日期选择器；「从剪贴板识别」。
5. 校园 V2 状态画板（4 张）。

**批次 B：社交闭环**

6. 报名确认 Sheet、结果（确认、候补、待核对）。
7. 发起活动（表单 V2：封面选择、日期选择器、步进器）。
8. 消息 V2：今天、更早分组，左滑已读，按类型图标。
9. 校园墙列表、帖子、发帖。

**批次 C：设置与低频**

10. 我的 V2、个人名片、提醒设置、外观与语言、举报与屏蔽、删除账号。
11. 重要事务全套（9 张 B 档重做）。
12. 邮箱（接入后）：列表、详情、提取截止。

**批次 D：系统级**

13. 小组件（小、中、锁屏）、实时活动（截止倒计时）。

## 6. 交互与动效规范（原生实现基准）

| 编号 | 场景 | 实现 | 数值 | 减少动态时 |

| M5 | Sheet | 原生 pageSheet 和可拖拽高度 | 系统 | 系统 |
| M6 | 倒计时 | 数字滚动变化 | 200ms | 直接变 |
| M7 | 下拉刷新 | 系统刷新控件，配轻触觉 | — | — |
| M8 | 保存或报名结果 | Toast 从顶部滑入，2.5 秒 | 弹簧 | 淡入 |
| M9 | 骨架屏 | 卡片骨架和微光 | 1.2 秒循环 | 静态灰块 |

## 7. 代码层问题与改造

| 问题 | 证据 | 影响 | 方案 |
|---|---|---|---|
| 没有导航栈 | 子页面用 `if(x) return <Screen/>` 替换，返回靠文字按钮 | 无右滑返回、无推入动画、返回丢滚动位置 | 引入 `@react-navigation/native-stack`（react-native-screens 已装）；分批把子页迁成栈页面 |
| 单行压缩代码 | `StudyScreen.tsx` 160 行，每行几百字符 | 不可审阅，改 UI 易引入回归 | 视图与 controller 分离，按 Pen 组件拆文件；新代码按常规格式 |
| 组件层薄 | V2 前只有 6 个基础组件 | 每页各自拼 Text 和 Button | `src/ui/Pen.tsx` 已起步，继续补 Sheet、Toast、Skeleton、日期选择器 |
| 类型检查报错 | `tsc` 在 `src/product` 报 10 个错（node 类型） | 交接文档写「通过」不准确 | 移动端 tsconfig 排除后端文件，或为共享类型单独建包 |
| 原生依赖增加需要重建 | haptics、日期选择器、分享扩展、Widget | dev client 要重新打包 | 集中一次加齐，重建一次 |
| 测试只测控制器 | 无 UI 级回归 | UI 重做时行为易坏 | 关键流程补组件测试和 Maestro 脚本（模拟器真点） |
| 演示数据混在验收库 | 「原生验收 · 候补递补」等标题 | 设计评审失真 | 分离 demo seed（已有 `.local/seed-demo.mjs` 雏形）与验收数据 |
| Tab 切换约 1 秒延迟 | 模拟器实测 | 体感卡顿 | 用 release 包复测；必要时惰性挂载和 memo |

## 8. 发散：如果我是这个产品的 PM

1. **「截止」是核心对象，不是「任务」的一个字段。** 学生的焦虑来自截止，所以首页、提醒、Widget、组队都围绕截止组织：截止 → 拆成任务 → 找人一起做（X01/X02）→ 完成。这把学习和社交两条线自然连起来，也是相对 USThing 的差异点。
2. **每日简报**：早上 8:00 一条本地通知「今天 2 节课，1 项今晚截止」，点开就是首页。这是最便宜的留存抓手，不需要远程推送。
3. **零授权优先，授权后增强**：Canvas 订阅、分享扩展、ICS 让产品第一天就有用；学校批准后自动升级成同步，用户不需要重新学习。
4. **截止倒计时实时活动**：今晚 23:59 截止的作业放在锁屏和灵动岛，是 iOS 独有、竞品少的体验。
5. **共同专注从截止开始**：截止详情页「找人一起赶」，直接建一个 50 分钟安静自习活动，复用现有活动系统。
6. **不做的事**：不做 AI 自动回邮件；不做公开效率排名；不收集学校密码。

1. ~~Canvas 个人订阅链接~~ → 已由用户决定改为参照 USThing 的学校账号登录（见文首修订）。PRD 原则 4 需改为：「不在本平台服务器保存学校密码或会话；学生在学校官方登录页登录，会话只留在本机。」
